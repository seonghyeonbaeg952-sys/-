# CMS 문구 편집 개선 · 릴리즈 전후 검증

대상: 홈페이지 문구 편집기, 문구 상자 줄간격, 편집 동시성, Spirit의 누락된 편집 대상과 NOW/NEXT 배치. 한국어 데스크톱 원문 및 기존 글자 서식은 임의로 교체하지 않았다.

## 변경과 범위

- 기존 편집 엔진을 유지하고 단일 기기 선택, 미리보기 도구 그룹, 선택 속성 패널, 펼쳐 보는 보조 도구로 UI 정리.
- Carbon 공식 SVG 4개만 직접 번들에 사용. 라이선스 및 SVG가 공식 패키지와 일치함을 확인. 새 production dependency 없음.
- 문구 상자별 `lineHeight`는 선택적인 0.8–3배 값. 기존 문서에는 새 값을 자동 생성하지 않음.
- 정직한 음악/성경 문구/계승/공동체/성장 문구 등 52개의 명시적 렌더러 키를 연결. 날짜·카운터·alt·메타데이터는 이 권한 목록에 넣지 않음.
- 편집 중 저장/게시/초기화를 버튼과 핸들러에서 차단. 초기화와 페이지 전체 서식도 실행 취소 이력에 포함.
- NOW/NEXT의 실제 글자 폭을 기준으로 본문 간격을 계산. NEXT의 들여쓰기를 줄여 본문을 넓힘. 기존 모션 타이밍 유지.

두 파일은 실제 production TypeScript 소스와 의존성을 읽는 작은 테스트 전용 로더를 공유한다. 테스트/검증 항목은 삭제하거나 건너뛰지 않았다. 격리 재실행에서도 해당 6개 테스트가 통과했다. 이 결과는 Windows 개발 환경의 모든 native worker 문제를 영구적으로 해결했다는 주장은 아니다.

- 최종 `pnpm lint`: 종료 코드 0.
- 최종 `pnpm build`: TypeScript 및 Vite production build 통과. plugin timing 안내가 있었으나 오류는 아님.
- `git diff --check`: 통과.
- 기본 public JSX/SSR 문구·태그·줄바꿈 계약 통과. 실제 기본값 변경을 감추도록 검사를 완화하지 않음.

## 실제 브라우저 검수

- CMS: 390×844, 768×1024, 1440×900에서 가로 넘침 0. 작은 checkbox의 클릭 라벨은 44px, 주요 입력·버튼은 최소 44px.
- 글꼴 창: 데스크톱 400×374px, 모바일 359.2×358px. 뷰포트 경계 안에 있고 가로 넘침 없음.
- 새로 연결한 `spirit.faith.paragraph0`를 실제 글자 편집으로 열고 입력·마침·실행 취소를 확인. 테스트 입력은 저장/게시하지 않고 원문으로 복원.
- 줄간격 2배: 16px 글자에서 실제 32px line-height와 64px 두 줄 높이 확인. 4배 오류, 입력 취소, 기본값 복원, undo/redo 확인. 기본값 복원 시 원래 28.16px line-height 사용.
- 인라인 입력 중 저장·게시·기기 변경 차단 확인. 숫자 입력/배치 반영과 같은 버퍼의 서식 편집은 각자의 완료 흐름을 유지.
- Spirit 한영: 실제 뷰포트 390, 768, 1024 가로, 1440, 1920의 10조건에서 기기 분류·9개 섹션 존재·본문/페이지 가로 넘침 확인. 일반 모션 및 reduced motion 확인.
- 공개 경로 8개 × 3크기 초기 렌더 확인. `/`, `/spirit`, `/about?section=spirit`, `conductor`, `accompanist`, `members`, `/join`, `/contact?section=support`.
- 반주자·단원·입단은 초기 로딩 화면만으로 끝내지 않고 실데이터 로딩 후 9조건을 추가 검수. 가로 넘침 및 error alert 없음.
- 실제 뷰포트와 요청한 크기가 일치하는지 검사. 효과가 없었던 상위 브라우저 크기 설정의 결과는 반응형 통과 증거로 사용하지 않음.

## 서버 및 보안

- `20261013050202_editor_text_box_line_height.sql`을 실제 Supabase 프로젝트의 내부 validator에 적용.
- 기존 문서, 경계값 0.8/3, 일반값 1.6은 수용. 0/0.79/3.01/음수/문자열/CSS 단위/null/객체/배열은 거부.
- validator의 `search_path`는 빈 값, security definer 아님. anon/authenticated 직접 실행 권한 없음. 관리자 save/publish RPC·RLS 구조 변경 없음.
- 테스트 전 한국어/영어 Spirit 초안과 공개본의 해시가 같고 대상 줄간격 override가 없음을 확인. 테스트 문구를 공개하지 않는다.
- 기존 `noindex`, 도메인 redirect, 보안 헤더 및 main 전용 자동 배포 설정 유지.

## 운영 CMS 검증

- 코드 커밋 `8183dbfba7678ccb977edb6782e236e0c3a7df3b`의 자동 production 배포 `dpl_4KgtXmGgaDi6BiHJfxEoqRL3zKBa`가 READY이고 실제 도메인에 연결되었음을 확인.
- 운영 CMS에서 한국어 데스크톱 `spirit.faith.paragraph0`의 줄간격만 1.65배로 바꾸고 **임시저장**. 새로고침 후 입력값 1.65가 유지되는 것을 실제 화면과 DB로 확인.
- **이 화면 게시**를 눌러 확인창이 열리고 변경 요약에 `줄간격 1.65배`가 표시됨을 확인한 뒤 **취소**. 최종 게시 버튼은 누르지 않음.
- 줄간격 기본값으로 복원하고 임시저장. 한국어 version은 114→115→116으로 증가했으나 최종 초안·게시본 MD5는 모두 검증 전의 `3274e016205e9084a5467705692e86ff`와 일치. 대상 layout override도 원래 null로 복원.
- 영어 version 83 및 초안·게시본 MD5 `7730496b9dca75e143ea4d620d65d9e5`는 검증 내내 그대로. 영어에서도 새 편집 대상을 실제 글자 편집으로 열고 변경 없이 마침을 확인.
- 운영 Spirit 한국어/영어 × 390×844, 768×1024, 1440×900의 6조건에서 실제 viewport와 기기 분류 일치, 9개 섹션, 가로 넘침 0, 브라우저 error 로그 없음 확인.
- 실제 도메인의 Spirit 응답은 HTTP 200 및 `X-Robots-Tag: noindex`. Vercel 기본 도메인은 HTTP 308로 실제 도메인에 redirect. DOM의 기존 robots meta는 `index, follow`이나 검색 제한은 응답 헤더의 `noindex`로 유지됨.
- 최종 운영 편집기의 상태는 **저장된 초안과 게시본이 같습니다**. 줄간격 입력을 키보드 Tab으로 이동해 44px 입력 영역이 속성 패널 안에 완전히 노출되는 것도 확인.

스크린샷·뷰포트 JSON·전체 테스트 로그는 저장소 외부 세션 검증 디렉터리에 보관. 테스트 문구와 테스트 줄간격을 공개 홈페이지에 게시하지 않았고, 한국어·영어 전체 문서가 원래 값으로 보존되었음을 해시로 확인했다.

## 조사 및 남은 리스크

40개 비교는 [비교표](2026-10-13-cms-editor-ui-comparison.md)에 출처·채택/제외 이유와 실제 조작 여부를 구분해 기록했다. 40개 Figma 파일을 다운로드하거나 전부 조작한 것은 아니다.

실제 iOS Safari와 물리적인 모바일 키보드/IME는 추가 확인 대상이다. Vercel 외부 log drain은 아직 설정되어 있지 않다. 새 배포의 runtime log MCP 조회는 403으로 거부되어 서버 로그를 통한 무오류 확인은 하지 못했다. 이는 정상 READY 배포 및 실제 브라우저 검증과 구분하며, 로그 권한이나 보안 설정을 임의로 완화하지 않았다.
