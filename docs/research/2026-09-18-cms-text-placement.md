# CMS 문구 자동 크기·정렬·배치 조사와 시안

작성일: 2026-09-18. 이 문서는 공식 자료 조사, 이 프로젝트의 설계 판단, 실제 Figma 시안을 구분해 기록한다. 공개 홈페이지의 기본 디자인을 바꾸는 제안이 아니다.

## 1. 조사 계획과 실제 범위

목표: 문서 편집기에 익숙한 운영자가 글자를 늘리거나 다른 문구와 위치를 맞출 때, 글자를 자르거나 주변 내용을 가리지 않고 원하는 기기의 초안만 수정하게 한다.

연구 질문:

1. 텍스트 양이 늘 때 박스 확장과 글꼴 축소를 어떻게 구분해야 하는가?
2. 박스 안 글자 정렬과 다른 박스 기준 정렬을 어떻게 구분하는가?
3. 글자 선택·스크롤·문구 이동이 충돌하지 않는 입력 방식은 무엇인가?
4. 드래그 없이도 이동하고 실수를 취소할 수 있는가?
5. 기기별 반응형 레이아웃에서 자유 배치의 안전 범위는 어디까지인가?

방법: 공식 문서 데스크리서치, 기존 CMS Figma 컴포넌트·토큰 확인, 시안 제작, 스크린샷과 노드 경계 검사. 실제 참여자는 0명이며 인터뷰·사용성 테스트를 수행한 것으로 보고하지 않는다. 아래 **고유 공식 문서 8개**의 해당 본문을 실제 확인했다. 재열기·검색 결과·언어판을 별도 건수로 세지 않았다.

## 3. 기본 UX 계약

### 자동 크기

- 문구가 길어지면 글꼴 크기를 유지하고 높이가 자연스럽게 늘어나야 한다. 박스 높이를 고정한 채 잘라내거나 폰트를 몰래 줄이지 않는다.
- ‘너비 자동’은 원래 반응형 레이아웃이 허용하는 너비를 사용한다. 무한한 한 줄 박스로 늘어나는 Figma Auto width를 웹에 그대로 옮기지 않는다.
- ‘너비 직접 설정’은 현재 섹션에 대한 폭으로 표시한다. 원래 배치를 건드리지 않으려면 자동값을 기본으로 두고 명시적 변경만 저장한다.
- 폰트 로딩·줄바꿈·편집된 내용으로 높이가 변하면 선택 테두리와 이동 손잡이도 다시 측정한다. 다음 콘텐츠는 문서 흐름을 따라 내려가야 한다.
- 조절 가능한 문구와 고정 크기 버튼/입력 컨트롤을 구분한다. 컨트롤 텍스트를 늘린다고 컨트롤이 다른 입력을 덮는 동작은 허용하지 않는다.

### 글자 편집과 이동 분리

- 기존 ‘글자 모양’ 옆에 ‘배치’ 탭을 둔다. 배치 모드의 전용 ‘문구 이동’ 손잡이에서만 드래그를 시작한다.
- 본문을 드래그하는 기본 동작은 글자 선택이다. 클릭했다고 바로 이동하지 않으며, 이동 중에는 캐럿 선택과 서식 변경을 동시에 실행하지 않는다.
- 방향 버튼, X/Y 입력, 기준 문구 정렬을 함께 제공한다. 드래그를 못 해도 모든 기본 배치 작업을 수행할 수 있어야 한다.
- 숫자 X/Y는 ‘원래 위치에서 이동한 거리’로 표시한다. 저장값이 오프셋인데 절대 좌표처럼 설명하지 않는다.
- 화살표는 이동 모드/손잡이가 포커스를 가진 경우에만 1px, Shift+화살표는 10px 이동한다. 본문·숫자 입력의 커서 이동과 한글 IME 입력을 가로채지 않는다.

### 두 가지 정렬

- ‘글자 정렬 · 박스 안에서’: 왼쪽, 가운데, 오른쪽. 위치를 바꾸는 기능이 아니다.
- ‘문구 박스 정렬 · 같은 섹션 기준’: 기준 문구 선택 후 좌우 가운데 또는 상하 가운데 맞춤. 기준 문구는 움직이지 않는다.
- 좌우 중심 맞춤은 X축만, 상하 중심 맞춤은 Y축만 바꾼다. 기준 문구와 이동 대상이 동일하거나 다른 섹션·숨김·다른 기기이면 선택할 수 없게 한다.
- 한 번 맞추는 명령과 계속 유지되는 상대 앵커는 다르다. 첫 구현이 px 오프셋만 저장한다면 내용 길이나 폭이 바뀐 뒤에도 중심이 영구 유지된다고 설명하지 않는다.
- 현재 기기의 실제 렌더링 박스 기준으로 맞춘다. DOM 문자열이 같다는 이유로 다른 문구를 기준으로 추정하지 않는다.

## 4. 안전 가드와 되돌리기

1. **기본 디자인 불변:** 배치 값이 없는 항목에는 기존 레이아웃이 그대로 적용된다. 전체 public 문구에 새 크기·위치 규칙을 일괄 덮어쓰지 않는다.
2. **현재 기기만:** 데스크톱/태블릿/모바일 범위를 항상 표시한다. 모든 기기 복제는 별도의 명시 동작 없이는 하지 않는다.
3. **현재 섹션 안:** 섹션 안의 허용 경계를 기준으로 이동을 제한한다. 섹션 밖으로 놓으려 하면 적용하지 않고 마지막 안전한 위치를 유지하며 이유를 알린다.
4. **겹침 탐지:** 같은 섹션의 다른 문구·입력·링크·버튼과 가림이 발생하면 경고한다. 제목을 가운데 맞춰 소개 문장 위에 겹치게 만드는 경우가 대표적이다. 중요한 조작 요소를 덮는 배치는 확정 전에 해결하도록 한다.
5. **삭제와 복원 구별:** ‘배치만 원래대로’는 해당 기기의 배치 오버라이드만 제거한다. 내용과 부분 서식, 다른 기기의 값은 지우지 않는다.
6. **취소 범위 명확:** Esc/pointercancel은 진행 중 이동만, 패널 취소는 이번 배치 세션만 되돌린다. 앞서 끝낸 글자 편집까지 몰래 되돌리지 않는다.
7. **한 동작 한 Undo:** 드래그 한 번, 숫자값의 명시 적용 한 번, 정렬 한 번을 각각 한 히스토리 단위로 묶는다. pointermove마다 수백 개 Undo를 만들지 않는다.
8. **모든 값 검증:** NaN/Infinity/빈 문자열/허용 범위를 벗어난 숫자는 저장하지 않는다. 0은 유효한 값이다. 잘못된 입력을 즉시 0으로 바꿔 입력 중인 사용자를 놀라게 하지 않는다.
9. **영속화 분리:** 마침은 배치 편집 종료이고 공개가 아니다. 기존 임시저장→미리보기→게시를 유지한다.
10. **지원 범위 등록:** 이동 가능한 문구만 등록된 어댑터로 노출한다. alt/aria/placeholder, 동적 CMS 행의 임의 반복 요소, 메뉴 컨트롤에 동일 배치 권한을 자동 확대하지 않는다.

## 5. 좌표·반응형 구현 참고

- 포인터 좌표는 브라우저 CSS 픽셀 기준이다. iframe/미리보기 축척의 역변환을 적용하고 devicePixelRatio를 중복 곱하지 않는다.
- 현재 박스·기준 박스·허용 영역을 같은 좌표계로 정규화한 뒤 `referenceCenter - currentCenter`를 계산한다.
- pointerdown 때 원래 값과 측정값을 스냅샷으로 보관한다. pointerup에서 확정하며 Esc/pointercancel/편집 대상 변경/기기 전환은 미확정 이동을 취소한다.
- 이동 중 화면 렌더링은 rAF로 묶고, 폭·줄바꿈·폰트 로딩으로 박스가 바뀔 때만 측정을 갱신한다. 모든 pointermove에서 전체 문서를 동기 측정하지 않는다.
- 스냅 가이드 임계값은 화면상 이동감과 일치해야 한다. 확대/축소에 따라 CSS 이동량이 달라지는 오류를 테스트한다.
- 좁은 화면은 패널을 가로로 줄이기보다 한 묶음씩 표시한다. 실제 스크롤은 손잡이 밖에서 계속 가능하게 하고 전체 문서의 touch-action을 막지 않는다.
- 위치·너비의 서버 검증은 기존 권한/카탈로그/기기 범위 검증을 통과해야 한다. iframe 메시지나 임의 CSS 문자열을 쓰기 권한으로 취급하지 않는다.

## 6. 실제 Figma 시안

기존 `691:2711`, `691:2897`, `706:1986`을 보존하고 같은 CMS 페이지의 오른쪽 빈 공간에 추가했다. 종이색·버건디·테두리 색 변수, 기존 버튼 인스턴스, Gothic A1 글꼴을 재사용했다.

전체 화면의 늘어난 제목은 동작 설명을 위한 **CMS 초안 예시**다. 실제 홈페이지 문구 변경 요청으로 처리하지 않았다. 공개 코드와 DB는 이 디자인 작업에서 수정하지 않았다.

실제 확인:

- 예시 제목의 폭 634.375px와 폰트 65.25px를 유지하면서 높이가 78px에서 155px로 증가했다. 소개 문장과 다음 목록이 아래로 따라 이동하는 것을 스크린샷으로 확인했다.
- 새 시안 4개의 스크린샷을 확인했다. 4개 루트의 가로 경계 초과는 0개, 남은 제작 중 placeholder는 0개였다.
- 배치 패널의 보이는 버튼은 모두 높이 44px 이상이며, 마지막 컨트롤 하단 782px는 패널 832px 안에 있다.
- 글꼴 읽기 검증: 도구/경고는 Gothic A1, 원래 홈페이지 미리보기는 Gothic A1/Hahmlet/Cormorant Garamond로 기존 구성과 일치했다.
- 전체 화면의 ‘상하 가운데 맞춤’에서 겹침 예시 오버레이를 열고 경고 버튼으로 닫는 Figma 반응 연결을 추가했다. 실제 좌표 이동·저장·게시를 수행하는 프로토타입은 아니다.

## 7. 구현 단계의 검증 과제

- 긴 한국어/영문/공백 없는 단어/줄바꿈/이모지/부분 글꼴: 높이 자동 확장과 다음 콘텐츠 흐름 확인.
- 배치 값 없음: 공개 페이지의 기존 위치·폭·폰트·문구가 바뀌지 않는 회귀 비교.
- 텍스트 드래그 선택과 이동 손잡이 조작의 분리, 빠른 탭 전환, 한글 IME 중 키 입력.
- XY 0/음수/빈 입력/소수/최댓값/범위 초과, 너비 자동/직접 설정/복원, 입력 후 취소.
- 같은 섹션 중심 맞춤에서 기준 문구가 움직이지 않음, 다른 섹션/기기/숨김 대상 제외.
- 축척 50%/100%/150%, 브라우저 확대 200%, iframe 스크롤, 폰트 로딩 후 가이드 재측정.
- pointercancel/Esc/창 밖 놓기/기기 전환/선택 삭제 시 미확정 이동 복구.
- 한 번 이동→Undo→Redo, 숫자 여러 필드 입력→적용 한 번→Undo 한 번.
- 390/768/1440 화면에서 패널 가림과 가로 overflow, 키보드/클릭 대안, 스크린리더 이름 확인.
- 임시저장 후 공개 화면 불변, 다시 열기, 충돌·네트워크 실패·권한 만료 시 입력 보존.

이번 조사·Figma 단계에서는 위 실제 CMS 테스트를 실행한 것으로 보고하지 않는다. 구현과 별도로 초보 운영자 3–5명에게 ‘긴 문구 수정’, ‘소개 문장 중심에 맞추기’, ‘모바일만 이동’, ‘취소와 복원’ 과제를 관찰하는 것을 권장한다.

## 8. 후속 배치 패널 구현과 자체 검토

후속 분담으로 `EditorPlacementToolbar.tsx`, 전용 `editor-placement-toolbar.css`, `EditorPlacementToolbar.test.mjs`를 추가했다. 모델·브리지·영속화·public 레이아웃은 별도 담당 작업이다. 원본 사이트 디자인을 변경하는 기본 배치값은 추가하지 않았다.

- 숫자 X/Y는 −2000–2000 CSS px, 너비는 10–100%의 로컬 입력으로 다루며 ‘위치·너비 적용’에서 한 번 반영한다.
- 방향 버튼은 미리보기에 즉시 반영하도록 한 클릭당 한 번 호출한다. 유효한 로컬 좌표가 있으면 그 위치에서 1px/Shift 10px 이동한다.
- 글자 정렬·기준 정렬·너비 자동은 관련 없는 미적용 좌표를 몰래 확정하지 않는다. 입력을 먼저 적용/취소하도록 안내한다.
- 적용 ACK 뒤 Undo 또는 A→B→A 선택 복귀 때 예전 숫자 입력이 다시 나타나던 문제를 실패 테스트로 재현한 뒤 수정했다.
- 이전 성공 메시지가 새 미적용 숫자를 ‘적용됨’으로 표시하던 문제도 실패 테스트 후 수정했다.
- desktop 도구는 미리보기를 아래로 밀지 않도록 우측 300px 컬럼을 사용한다. 1100px 이하에서는 단일 컬럼, 높이 `min(340px,40dvh)`의 스크롤 패널로 바꾼다. 실제 렌더링 검증은 통합 담당자가 진행한다.
- 기존 글꼴 툴바를 바꾸거나 또 다른 창 드래그 시스템을 만들지 않았다. 모든 새 CSS는 배치 패널과 편집 영역 클래스에 한정했다.
- 페이지/기기 전환은 부모의 `${page}:${device}` key로 분리하며, 컴포넌트 내부에서도 선택 문구·확정 값 변경을 감지해 로컬 입력을 초기화한다.

자체 검토 항목: 입력 라벨과 오류 연결, 44px 조작 영역, 긴 라벨 줄바꿈, 숫자 단일 적용, 유효성 검사, 즉시 nudge, IME/수정키 보호, 동일 섹션 기준 선택, ACK/Undo 복구, 실패 입력 보존, 미적용 상태 표시, 기존 관리자 선택색/hover와 CSS 범위. 이는 코드 기반 자체 검토이며 실제 브라우저 검증을 대체하지 않는다.

미적용 숫자를 입력한 채 페이지·기기·모드를 바꿔 잃지 않도록 `onDirtyChange`를 추가했다. 입력 직후 동기적으로 잠금을 알리고, 적용 ACK/입력 취소/초기화/언마운트에서 해제한다. 방향 이동 요청이 아직 ACK되지 않았다면 잠금을 유지한다. 이 잠금은 부모의 전역 이동 컨트롤에만 합치며, 자기 숫자 입력·적용·취소 버튼을 비활성화하지 않는다.

실행 결과: `node --test src/components/admin/site-editor/EditorPlacementToolbar.test.mjs` **29/29 통과**, 해당 TSX `pnpm exec eslint` 통과. 앞선 통합 시점의 `pnpm exec tsc -b --pretty false`도 통과했다. 테스트는 실제 컴포넌트의 핸들러/로컬 상태를 실행하는 기존 프로젝트 방식의 훅 하네스이며 실제 React DOM의 포커스·배치 검증과 구분한다.

시안의 가이드/스냅 체크박스는 상호작용 제안이다. 합의한 컴포넌트 props에는 해당 명령이 없어 실동작하지 않는 토글을 코드에 넣지 않았다. 실제 자동 스냅·가이드 표시, 포인터 취소, 섹션 경계·겹침 정책은 런타임 구현과 통합 테스트 결과로 별도 확인해야 한다.

## 9. 공개 홈페이지 실제 브라우저 회귀 검사

2026-09-18, `http://127.0.0.1:5175`의 실제 앱을 Chrome 전용 임시 검증 탭에서 읽기 전용으로 확인했다. IAB는 이 검증 세션에 연결되지 않아 Chrome으로 대체했다. 기존 사용자 탭과 통합 담당자의 5177 CMS 탭은 조작하지 않았다. 폼 제출, 관리자 이동, 저장·게시, DB 변경은 하지 않았다.

측정 조건은 해당 탭에만 CDP `Emulation.setDeviceMetricsOverride`를 적용한 390×844, 768×1024, 1440×900 CSS px, DPR 1이다. 이는 세 화면 폭의 Chromium 반응형 검사이며 실제 iOS/Android 터치 기기 검사는 아니다. Windows 기본 세로 스크롤바 15px가 있어 문서 clientWidth는 각각 375/753/1425px였다.

`load`와 제목 노출 후 공개 데이터 요청 완료를 관찰하고, 초기 빈 데이터 안내가 아닌 실제 본문을 확인했다. 아래 셀은 **문서 가로 넘침(px) / body.innerText 문자 수**다. 본문 문자 수는 반응형으로 숨겨지는 메뉴·장식·문구 때문에 화면 폭별로 다를 수 있으며 콘텐츠 동일성의 해시가 아니다.

실제로 본 스크린샷의 시각 판단:

- **390px 갤러리:** 제목·사진/영상/포스터 탭·분류·사진·설명이 한 컬럼 안에 들어왔다. CMS 선택 테두리나 화면 밖 가로 잘림은 보이지 않았다.
- **390px 홈:** 메인 제목, 소개, 입단 안내/공연 일정 CTA와 슬라이드 컨트롤이 화면 안에 보였다. 제목과 CTA가 서로 덮이지 않았다.
- **768px 입단 안내:** 제목과 지원서 CTA, 네 가지 안내 탐색, 모집 대상이 자연스럽게 세로로 이어졌으며 제목·버튼 잘림은 보이지 않았다.
- **1440px 지휘자 소개:** 탐색 버튼과 제목, 왼쪽 프로필·오른쪽 공연 사진의 두 열이 표시되었다. 진입 페이드 중의 옅은 프레임과 애니메이션 종료 후 선명한 프레임을 구분해 확인했다.
- **1440px 홈:** 배경 사진·메인 제목·CTA·하단 주요 바로가기가 표시되었다. 화면 폭 전환 직후의 이전 프레임/일시적 빈 프레임은 최종 시각 결과로 사용하지 않았다.

기존 기본 디자인 보존의 검증 범위는 ‘새 편집 표시가 공개되지 않음, 기본 공개 라우트가 렌더됨, 측정한 폭에서 가로 overflow 없음, 위 실제 스크린샷 상태 확인’이다. 이전 커밋과의 픽셀 단위 이미지 비교 또는 모든 스크롤·팝업 상태까지 동일함을 증명한 것은 아니다.

별도 기존 위험: 데스크톱 홈 공연 영역의 링크 일부가 `/sample/concerts`, `/sample/concerts/<id>`, `/sample/contact?section=performance`로 향한다. `git show HEAD:src/components/sample/home-v4/HomeV4PerformanceCarousel.tsx`에서도 동일한 네 링크를 확인해 이번 배치 구현 이전의 상태로 분류했다. 이 회귀 검사에서는 디자인·링크를 수정하지 않았으며, 기존 공개 데이터인 ‘시안2’ 등도 이번 검증에서 생성한 테스트 데이터가 아니므로 삭제하지 않았다.

검사 종료 후 전용 탭의 viewport override를 해제하고 Network 관찰을 종료한 뒤 그 임시 탭만 닫았다. 기존 사용자 탭은 보존했다.
