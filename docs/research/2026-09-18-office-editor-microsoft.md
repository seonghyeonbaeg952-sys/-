# 문서 편집기 공통 UX 조사 — Microsoft Word·PowerPoint

확인일: 2026-09-18. 공식 문서 8개를 실제 열어 관련 본문을 확인했다. 검색 결과 수·언어별 중복·같은 페이지 재열람을 조사 건수에 더하지 않았다. 실제 사용자 인터뷰나 Microsoft 앱 사용성 실험은 수행하지 않았다.

## 연구 질문과 방법

대상은 홈페이지 관리 경험이 적지만 한글·워드·PPT를 사용하는 관리자다. 공개 홈페이지 디자인을 유지하면서 글자 편집의 학습 부담을 줄이는 것이 목적이다.

1. 어떤 선택·서식 변경 순서가 제품 간에 공통적인가?
2. 어떤 단축키가 실제로 같고, 어떤 것은 제품·플랫폼에 따라 다른가?
3. 글자 서식과 문단 서식을 어떻게 구분하는가?
4. 터치 화면에서는 동일 작업을 어떻게 노출하는가?
5. 문서 저장 방식 중 웹사이트 게시와 구분해야 할 것은 무엇인가?

방법은 공식 도움말 기반 비교 조사와 현재 CMS의 설계 검토다. 조사 대상은 제품 기능이며 연구 참여자는 없다. 설치된 앱에서 직접 관찰했다고 표현하지 않는다. 출처별 관찰과 프로젝트에 적용한 판단을 구분한다.

## 채택할 공통 상호작용

- 화면 문구를 선택하고 그 자리에서 입력한다. 드래그·Shift+방향키로 부분 선택을 유지한다.
- 글꼴 이름과 크기는 직접 읽고 조절할 수 있게 한다. 크기는 웹의 px 단위를 표시하고 Office의 pt인 것처럼 표시하지 않는다.
- 선택한 글자의 색·굵기·기울임·밑줄·취소선을 변경한다. 문단 정렬·행간은 별도 범주로 두고 문자 범위 서식인 것처럼 저장하지 않는다.
- 되돌리기·다시 실행과 서식 지우기를 구분한다. 선택한 글자 이외의 문구를 몰래 바꾸지 않는다.
- 제품마다 다른 서식 복사 단축키를 한 가지 공통 표준이라고 주장하지 않는다. 먼저 명시적인 버튼을 제공한다.
- 브라우저의 Ctrl+L/R, 새 탭·닫기 등 탐색 단축키를 문서 앱처럼 전역 가로채지 않는다.
- 한글 조합 중 단축키·도구 적용·DOM 갱신으로 조합 문자열을 확정하거나 잃지 않는다.

## CMS에 필요한 차이

오피스의 저장/자동 저장은 방문자에게 홈페이지 변경을 공개하는 동작과 다르다. CMS에서는 ‘임시저장’과 ‘게시’를 계속 분리한다. Ctrl+S를 지원한다면 임시저장만 수행하고, 현재 입력을 안전하게 반영할 수 없으면 내용을 보존한 채 안내한다.

아직 저장되지 않은 입력을 Esc만 눌렀다고 지우지 않는 방향으로 기존 시안을 개선한다. 입력을 마치는 행동과 편집 이전 상태로 되돌리는 행동은 구분한다. 실제 구현에 앞서 기존 계획의 Esc 취소 계약과 테스트를 명시적으로 갱신해야 한다.

공통 기능을 조사했다는 이유로 표·도형·쪽 나누기·요소 자유 이동·매크로·임의 HTML 등 홈페이지 관리 범위를 넘는 도구를 추가하지 않는다. 정확한 서식 적용·선택 유지·취소·저장 복구가 먼저다.

## 검증 과제

공식 문서 관찰은 사용성 검증을 대신하지 않는다. 실제 CMS에서 다음을 확인해야 한다.

1. 제목 일부만 선택해 색·서체·크기를 바꾸고 다른 글자는 그대로인지 확인.
2. 서식 도구를 눌러도 선택 범위가 유지되는지 확인.
3. 한글 조합과 부분 교체 후 undo/redo로 입력·서식·커서가 복구되는지 확인.
4. 임시저장만 한 뒤 공개 홈페이지가 바뀌지 않는지 확인.
5. 모바일 기본 선택 핸들과 가상 키보드가 서식 도구에 가리지 않는지 확인.
6. 혼합 서식·서식 지우기·잘못된 크기·색 입력의 결과가 명확한지 확인.

현재 문서는 조사·설계 근거다. 위 구현 검증을 통과했다는 기록이 아니다.
