# 한컴 한/글 문서 편집 상호작용 조사

조사일: 2026-09-18

목적: 홈페이지 CMS의 실제 화면 위 문자 선택·서식 편집을 설계할 때, 한/글 사용자가 익숙한 동작을 근거로 채택하고 제품별 차이를 분리한다.

## 조사 범위와 확인 수준

- **한컴 공식 도움말 11개 URL을 실제 열람했다.** 아래 원장은 모두 `help.hancom.com`의 설치형 **한/글(Hwp)** 도움말이다. 같은 문서의 검색 결과와 본문 열람을 별도 건수로 세지 않았다.
- `hoffice/multi` 문서는 제품 연도를 명시하지 않는 공통 도움말이다. `hoffice130_assistant` 단축키 문서도 URL의 내부 버전을 임의로 출시 연도로 바꾸지 않았다. 이 조사만으로 최신 모든 배포판의 실제 동작을 단정하지 않는다.
- 웹에 게시된 도움말이라는 사실은 **웹 한글 제품의 동작을 검증했다는 뜻이 아니다.** 웹 한글·한워드 도움말 열기 시도 2건은 실패했으며, 확인 문서 수에 포함하지 않았다.
- 설치형 한/글 앱에서 직접 조작한 결과가 아니라 **공식 문서 조사**다. 터치, 브라우저 IME, 브라우저 클립보드 권한, 저장·공개 동작은 아래 11개 문서로 검증되지 않았다.
- 한쇼(HShow), 한셀(HCell), Mac용 자료는 검색 결과에 있더라도 이번 원장에서 제외했다. 한워드(Hword)와 한/글(Hwp)도 같은 제품으로 취급하지 않는다.
- 이전 조사나 병렬 Microsoft 조사 수량과 합산하지 않는다. **50,000건을 확인했다는 주장은 하지 않는다.**

## 공식 자료 내부 불일치

[서식 도구 상자](https://help.hancom.com/hoffice/multi/ko_kr/hwp/view/toolbar_formatting.htm)는 다시 실행을 Ctrl+Y로 표기한다. 그러나 [상세 다시 실행 도움말](https://help.hancom.com/hoffice/multi/ko_kr/hwp/edit/redo.htm)과 [별도 단축키 일람](https://help.hancom.com/hoffice130_assistant/ko-KR/Hwp/view/toolbar/shortcut%28table%29.htm)은 Ctrl+Shift+Z를 명시하고, 후자는 Ctrl+Y를 한 줄 삭제로 명시한다. 도구 상자의 밑줄 행도 Alt+Shift+I로 적혀 있지만, [글자 속성](https://help.hancom.com/hoffice/multi/ko_kr/hwp/format/font/fonts%28font_style%29.htm)과 단축키 일람은 Alt+Shift+U / Ctrl+U를 제시한다.

따라서 도구 상자 페이지의 일부 표기를 그대로 옮기지 않는다. 이 조사에서는 상세 기능 문서와 별도 단축키 일람이 일치하는 값을 우선했지만, 설치형 앱의 실제 버전별 확인을 대신하는 것은 아니다.

## CMS 설계에 채택할 패턴

아래는 문서에서 확인한 동작을 바탕으로 한 **프로젝트 설계 제안**이다. 한컴이 웹 CMS에 이 구현을 권장한다는 의미는 아니다.

### 1. 요소 선택과 문자 편집을 두 단계로 구분

실제 페이지에서 한 번 클릭하면 편집 가능한 텍스트 요소를 선택하고, 더블클릭 또는 명시적인 ‘문자 편집’ 동작으로 입력 상태에 들어간다. 입력 상태에서는 드래그·Shift+방향키·단어 선택 등 브라우저 문자 선택을 유지한다. 한/글의 ‘더블클릭 단어 선택’은 **이미 문자 편집 중인 상태**의 동작과 비교해야 하며, 비편집 상태의 더블클릭 진입과 혼동하지 않는다.

터치에서는 첫 탭으로 요소를 선택하고 눈에 보이는 편집 버튼으로 진입한다. 길게 누르기와 선택 핸들은 브라우저 기본 동작을 우선한다. 이 터치 제안은 이번 설치형 도움말에서 검증된 패턴이 아니므로 실제 모바일 브라우저 검증이 필요하다.

### 2. 서식 적용 범위를 먼저 명확히 표시

- 문자 범위 선택: 선택한 문자만 변경한다.
- 커서만 있음: 앞으로 입력할 문자의 서식을 변경한다. 이 기능이 구현되지 않았다면 비활성화 사유를 표시하며 전체 문장에 대신 적용하지 않는다.
- 바깥 요소 선택: ‘전체 문구에 적용’을 명시적으로 선택한 경우에만 전체 범위를 대상으로 한다.
- 혼합 서식: 글꼴·크기·굵게 등의 값이 하나인 것처럼 표시하지 않고 ‘혼합’ 상태를 보여준다.
- 도구 모음을 클릭해도 기존 선택 범위를 보존한다. 단, 소스나 초안 버전이 바뀌면 이전 범위를 추정하여 재사용하지 않는다.

### 3. 첫 화면의 도구는 문자 편집 중심으로 제한

주요 도구는 글꼴, 크기, 굵게, 기울임, 밑줄, 글자색이다. 취소선은 확장 메뉴로 둘 수 있다. 문단 정렬·줄 간격·자간·그림자·테두리·위치 이동은 기존 홈페이지 레이아웃을 바꾸는 별도 기능이므로, 한/글에 있다는 이유로 이번 문자 편집 범위에 포함하지 않는다.

부분 서식은 선택 범위의 허용 속성만 덮어쓴다. 다른 문자, 다른 속성, 기존 강조 요소, 반응형 기본 크기를 일괄 초기화하지 않는다. 공개 페이지의 초기 글꼴·크기·간격·DOM은 사용자가 실제로 서식을 저장하기 전까지 유지한다.

### 4. 서식 복사는 명시적 모드로 후속 도입

서식 복사는 사용자에게 익숙한 후보 기능이지만, 선택·부분 서식·되돌리기가 먼저 안정되어야 한다. 도입할 때는 복사 대상이 ‘글자 서식’임을 표시하고, 현재 허용한 속성만 복사한다. 출처와 활성 상태를 표시하고 적용 후 모드를 끝내는 일회성 동작을 기본으로 한다. 여러 대상 연속 적용은 별도 명시 옵션이다.

‘서식 지우기’ 역시 선택한 범위의 사용자 지정 문자 서식을 제거해 사이트 기본값으로 돌아가는 동작으로 정의한다. 텍스트 내용 삭제, 서버 초안 폐기, 페이지 기본 디자인 재설정과 분리한다.

### 5. 되돌리기는 글자와 서식을 함께 다룸

텍스트 입력, 선택 범위 대체, 삭제, 서식 변경을 사용자 행동 단위로 되돌린다. 새로운 변경을 하면 재실행 분기는 끊어진다. IME 조합 중간 결과를 각각 독립 작업으로 기록하지 않는다.

현재 입력 세션의 브라우저 되돌리기와 부모 CMS 초안의 되돌리기를 동시에 실행하지 않도록 상태별 소유자를 정해야 한다. 저장·공개·복원은 서버 상태를 바꾸는 별도 동작이며, 입력 되돌리기 버튼이 이미 공개한 버전을 취소하는 것처럼 보이면 안 된다.

## Microsoft Windows 앱과 비교할 때 주의할 단축키

Microsoft Word/PowerPoint 공식 자료는 [별도 Microsoft 조사 기록](2026-09-18-office-editor-microsoft.md)에 정리했다. 아래 표의 한/글 열은 이번 원장의 근거이며, ‘공통’ 판정은 **동일한 편집 상태와 동일한 플랫폼**의 Microsoft 자료가 확인된 항목에만 내려야 한다. 두 연구의 문서 건수는 합산하지 않는다.

## 이 CMS의 마침·취소·저장 계약

다음은 한/글 문서의 결론이 아니라 기존 CMS 설계와 데이터 손실 방지 원칙에 맞춘 **명시적인 제품 계약**이다.

1. 문자 편집을 시작하면 현재 소스와 부분 서식을 기준으로 활성 입력 트랜잭션을 만든다.
2. ‘편집 마침’, F2, 또는 조합 중이 아닌 Esc는 이 트랜잭션을 **부모 로컬 초안에만 안전하게 반영**한 뒤 요소 선택 상태로 돌아간다. 서버 저장이나 공개가 아니다. 부모의 검증·승인 전에는 입력을 완료된 것으로 표시하지 않으며 실패·충돌·응답 유실 시 버퍼와 선택을 보존한다.
3. 현재 입력을 포기하는 동작은 명시적인 **‘이번 편집 되돌리기’ 버튼**으로 분리한다. 이 버튼만 현재 활성 입력 트랜잭션을 취소한다. 이미 마친 다른 변경은 유지하고, 일반적인 실수 복구는 Ctrl/Cmd+Z로 제공한다. 요소 선택 상태에서 Esc는 선택만 해제한다.
4. 한글 IME 조합 중에는 Esc·Enter·F2를 CMS 단축키로 가로채지 않는다. Ctrl+Enter는 마침 별칭으로 등록하지 않는다. 조합 종료와 마침 이벤트의 순서도 실제 브라우저에서 검증한다.
5. 도구 모음 클릭은 문자 선택을 유지한다. 다른 요소 선택이나 바깥 클릭 때문에 입력을 조용히 폐기하지 않는다. 필요한 경우 ‘편집 마침’ 또는 ‘이번 편집 되돌리기’를 명시적으로 선택하도록 안내한다.
6. 서버 ‘초안 저장’과 ‘공개 반영’은 별도 버튼·상태·실패 안내를 갖는다. 공개되지 않은 변경을 공개 상태처럼 표시하지 않는다.

## 소스 매핑과 보안에 대한 적용 한계

- 화면의 비슷한 문자열을 찾아 교체하는 방식은 사용하지 않는다. 부모가 신뢰하는 어댑터·카탈로그·현재 문서·기기별 기본값으로 원본을 재구성한 경우에만 편집 권한을 준다.
- exact 원본, 명시적인 UTF-16 slice, 검증된 다중 조각 매핑을 구별한다. 선택 범위가 여러 소스에 걸리면 역변환·원자적 저장·충돌 처리가 증명되기 전에는 자동 분배하지 않는다.
- 미리보기에서 받은 `fullText`, 소유 페이지, 저장 범위, 스타일 목록을 그대로 신뢰하지 않는다. 부모 초안의 원본·리비전과 일치하는 권한에 한해 반영한다.
- URL, alt, aria, placeholder, 동적 공연/공지/단원 정보 등은 화면에 보인다는 이유만으로 일반 문자 편집 권한을 주지 않는다. 공통 푸터를 편집하는 경우에도 실제 소유 문서는 `common`이며 현재 화면 페이지로 저장하지 않는다.
- 외부 HTML·CSS를 그대로 붙이지 않는다. 텍스트 및 검증된 문자 서식만 허용하고, 원시 HTML·이벤트 속성·임의 CSS·외부 글꼴 URL은 받지 않는다.
- 한컴 문서는 이 프로젝트의 인증·메시지 검증·CAS 정책을 증명하는 자료가 아니다. 위 항목은 별도의 코드 근거와 보안 테스트가 필요한 설계 제안이다.

## 구현 전후 검증 게이트

1. **기본 디자인 불변:** 편집 모드 밖에서 기존 DOM·텍스트·기본 스타일을 유지한다. 데스크톱/태블릿/모바일의 기존 강조와 줄 분리를 확인한다.
2. **문자 선택:** 드래그, Shift+방향키, 단어 선택, 선택 범위 대체가 exact와 slice 어댑터에서 같은 의미로 동작한다.
3. **부분 서식:** 선택 문자만 변하며 기존 다른 속성과 다른 문자 서식은 유지한다. 혼합 값과 빈 선택을 구분한다.
4. **커서·도구 모음:** 도구 클릭 뒤에도 대상 범위를 유지하며, 커서 이동 후 이전 위치의 서식 표시가 남지 않는다.
5. **IME:** 한글 조합·후보 선택·조합 취소 중 마침/취소 단축키가 중복 실행되지 않는다. 조합 결과가 한 번만 반영된다.
6. **되돌리기:** 입력·삭제·서식·마침의 경계를 확인한다. 새 변경 후 재실행을 차단하고, 다른 페이지 기록과 섞지 않는다.
7. **마침·취소:** Esc/F2/편집 마침은 같은 검증·승인 경로로 로컬 초안에 반영한다. 실패 시 입력을 보존한다. ‘이번 편집 되돌리기’만 현재 입력을 취소한다. Ctrl+Enter는 마침으로 동작하지 않고, 바깥 클릭으로 입력이 유실되지 않는다.
8. **붙여넣기:** 일반 텍스트, 줄바꿈, 한/글·Word에서 복사한 내용, 허용하지 않은 HTML을 검증한다. 지원하지 않는 서식은 안전하게 제거한다.
9. **소스·소유권:** 원본 불일치, 오래된 미리보기, 기기 범위 차이, 다른 페이지 소유권, 편집 금지 필드에 권한이 나가지 않는다.
10. **실제 환경:** 390px·768px·1440px, 확대 200%, 키보드만 사용, 터치 선택, 모바일 키보드, 저장 실패/재시도를 확인한다. 특히 iOS Safari 및 실제 한글 IME 검증 여부를 보고서에서 구분한다.

## 인계 요약

한/글에서 가져올 핵심은 ‘선택한 문자만 변경’, ‘자주 쓰는 서식의 직접 조작’, ‘입력과 서식의 되돌리기’, ‘복사/적용 범위를 구분한 서식 복사’다. 단축키 전체, 문서 구조 편집, 데스크톱 클립보드 권한까지 그대로 가져오는 것은 아니다.

이 문서는 코드 변경이나 실제 앱 검증 완료를 의미하지 않는다. **공식 문서 11개 실제 열람, 웹 자료 2개 열기 실패, 설치형 앱 직접 실행 미실시**가 이번 조사 범위다.
