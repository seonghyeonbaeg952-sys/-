# CMS 브라우저 검증 진행 기록

2026-09-17 작업의 중간 증거다. 전체 계획 완료 보고서가 아니다. 브라우저는 실제 React 앱을 사용하는 `127.0.0.1:5177` 격리 환경이며, Supabase 모듈을 합성 transport로 대체하고 CSP로 외부 연결을 막았다. 운영 개인정보나 운영 게시본을 변경하지 않았다.

## 확인한 흐름

- 1440px 편집기: 한 개 화면 선택창, 기기별 초안, 별도 임시저장·게시, 잘못된 디자인 수치 차단, 미리보기, 합성 게시 확인.
- 뒤로가기에서 미저장 입력이 사라지는 현상을 먼저 재현했다. 데이터 라우터 경계와 `useBlocker`를 연결한 뒤 뒤로가기·메뉴 이동에서 확인창이 나타나고, 계속 편집 시 `QA Back Guard 456` 입력이 유지되는 것을 스크린샷으로 확인했다.
- 매우 빠른 상태 변경→뒤로가기에서 passive effect 전에 경고를 건너뛰는 틈을 재현했다. 폼의 동기 dirty 알림과 layout effect 등록 후, 같은 연속 조작에서 원문 모달 위 이탈 확인창이 나타나는 것을 확인했다.
- 중첩 확인창에서 Escape는 위 확인창만 닫고 ‘처리 중’ 입력을 유지했다. 명시적 나가기 후 `dialogs=0`, body overflow 원복을 확인했다.
- 768px 후원약정 상세: 처음 열면 마지막 상태 필드로 스크롤되는 문제를 발견했다. 문서 순서의 첫 사용 가능 동작에 포커스를 주도록 수정한 뒤, 위쪽 원문·인쇄 영역부터 열리는 스크린샷을 확인했다.
- 후원약정 print CSS emulation: 별도 접수 답변/동의/서명 이미지 요소/약정 원문/마지막 안내가 표시되고 관리자 폼과 메뉴는 제외됨을 확인했다. 검증 후 emulation을 해제했다. 작은 합성 PNG가 큰 정사각 공백을 만들 수 있어 서명 출력 높이를 30mm로 제한했다. 실제 손서명 진위나 물리 프린터·PDF 페이지 나눔을 검증한 것은 아니다.
- 합성 공지 31개: 첫 페이지 25개, 다음 페이지 6개, 마지막 페이지 다음 버튼 비활성 확인. 공개 노출은 모두 false인 합성 자료다.
- 390px 접수 보호 설정: 접힌 고급 영역을 열어 현재값 100/5 확인. 9 입력은 오류와 입력 보존, 120은 격리 서버에 저장 성공. 다른 두 접수 유형은 100 유지. 가로 크기 `innerWidth=390`, `scrollWidth=375`, 화면 배치 확인. 실제 운영 제한값은 변경하지 않았다.
- 공개 `/spirit`: 새 라우터/문구 어댑터 적용 후 실제 제목·섹션·메뉴·푸터 렌더링 확인. 이는 모든 공개 route/viewport의 시각 비교 완료를 의미하지 않는다.

## 실행 검증

- 321개 전체 자동 테스트, lint, build 통과 시점 확인. 이후 추가한 접수 제한 API 3개 테스트도 독립 통과. 이후 변경을 포함한 최종 전체 재실행이 필요하다.
- 공개 고정 문구 기본 JSX 비교: 48개 파일 통과. 소개 6종의 이전 SSR 해시 통과.
- 공개 import graph에서 CMS 카탈로그와 eager admin 경계를 제거하는 테스트 RED→GREEN.
- 기능별 RED→GREEN: 새 약정서 재접수 ID, 후원 원문/인쇄, 구조화 원문 테이블 안전 표시, 범위 조회/페이지 이동, 입단지원 집계, 포커스·중첩 스크롤 잠금, 빠른 미저장 보호, 제한값 CAS.

## 동일 작업본의 번들 비교

CMS lazy 경계와 홈 편집 어댑터 분리 직전/직후 build output을 비교했다. 전체 앱 다운로드나 실제 로딩 시간 측정과 구분한다.

| 출력 | 직전 | 직후 |
|---|---:|---:|
| index JS | 158.51 kB / gzip 43.77 kB | 143.23 kB / gzip 40.46 kB |
| index CSS | 248.15 kB / gzip 41.64 kB | 242.46 kB / gzip 40.69 kB |
| CMS 스타일 | 초기 index에 포함 | 별도 관리자 chunk 약 5.68 kB |

1097개 편집 정의가 담긴 카탈로그는 관리자 편집 화면 chunk에만 남는다. public 홈은 `homeEditorOverrides`의 기존 기기별 어댑터만 사용한다. 공개 route별 CSS chunk는 이 분리에서 그대로 유지되었다.

## 남은 확인

모든 public route의 390/768/1440 및 200% 확대, 입단/문의/약정 실접수 차단 회귀, 실제 DB 동시 세션 경합, Storage 공개·비공개 자산 경계, 배포 보안 헤더/의존성, 최종 인쇄·모바일/키보드 비교, 추가 고정 문자열 감사, 사용 설명서와 최종 계획 대조는 아직 남아 있다. 테스트 수만으로 전체 완료 처리하지 않는다.

## 추가 검증 — 2026-09-17 후속

- 의존성 업데이트 후 `pnpm test` **336/336**, `pnpm lint`, `pnpm build` 통과. known dependency advisory 0. 아래 추가 SQL 변경은 별도 DB 계약으로 확인한다.
- 모바일 CMS 문구 검색에서 `기다립니다`로 찾은 입력을 전혀 다른 문장으로 바꾸어도 입력창이 활성 상태로 남고 미저장 1개로 표시되었다. 되돌리기로 검증 문구를 제거했다. `문구 더 보기`에서 실제 필드 수 20→40, 남은 44→24를 확인했다.
- CUA의 `fill('')`는 이 환경에서 실제 검색어를 지우지 않았다. Control+A/Backspace로 지워 검색 결과와 전체 목록 원복을 확인했다. 이를 제품의 검색 초기화 결함으로 기록하지 않는다.
- 공개 경로 `/`, `/spirit`, 소개의 conductor/accompanist/members/history, `/join`, `/contact?section=support`, `/concerts`, `/notices`, `/gallery?tab=photos`를 390/768에서 실제 방문하여 initial render와 Vite 오류 overlay 부재 확인. 문서 폭은 각각 375/753으로 viewport 초과 없음. 1440도 위 경로 및 `/about?section=spirit`에서 문서 폭 1425 확인.
- 빠른 연속 경로 검사에서 일부 About 초기값은 데이터 로딩 전 빈 상태였다. 이 결과는 전체 사진·데이터가 다 로딩된 최종 시각 비교가 아니다. 연혁은 별도로 실제 제목과 이미지 4/4 로딩 완료 확인. 모바일 갤러리는 사진 로딩 후 스크린샷을 검토했고 현재 탭 console error/warn 0개.
- 홈 hold effect 변경 전/후 1440px 상단 `before`, 하단 `ended`를 확인했다. 기존 고정 기준·CSS는 유지한다. 80개 scroll burst의 프레임 계산 감소는 자동 테스트에서 측정한 것으로 실제 FPS 향상 측정이 아니다.
- 실제 200% 브라우저 확대는 키 입력을 시도했지만 측정 viewport가 기대대로 변하지 않아 검증 완료로 집계하지 않는다. 임시 확대 키 설정은 Control+0으로 원복했다.
- 사용 설명서와 현재 결과를 각각 `cms-operator-guide.md`, `cms-audit-results.md`에 추가했다. 위 ‘남은 확인’의 의존성·가이드 항목은 이 기록으로 갱신하되, 전체 재귀 검증 완료로 간주하지 않는다.
- 5177 검증 서버 종료, 검증용 탭 4/5 닫기, viewport/print/device emulation 원복. 검증용 임시 폴더 삭제는 실행 정책에 거부되어 수행되지 않았다. 초기 담당자 증거는 `cms-initial-qa-evidence.md`에 당시 보고서임을 표시해 보존했다.
