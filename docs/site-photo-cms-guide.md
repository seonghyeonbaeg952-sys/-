# 홈페이지 사진 관리

관리 메뉴의 **홈페이지 사진 관리** (`/admin/photos`)에서 현재 공개 홈페이지의 사진, 로고, 배경과 단독 장식 이미지를 교체한다. 문구·번역·배치 문서는 이 화면에서 수정하지 않는다.

## 사용 순서

1. 사진 이름·사용 페이지로 검색하거나 사진 종류를 선택한다.
2. 사용 화면 링크로 해당 위치를 확인하고 **사진 교체**를 누른다.
3. 파일을 선택한 뒤 **선택한 이미지 업로드**를 누른다. JPG/PNG/WebP, 최대 5MB이며 새 파일 경로를 사용한다.
4. 현재 공개 사진과 교체 미리보기를 비교한다. 불러오지 못한 사진은 저장할 수 없다.
5. 고정사진은 **사진 초안 저장 → 사진 게시**를 누른다. 초안 저장만으로 공개 화면은 바뀌지 않는다.
6. 히어로·인물·공연·공지·갤러리·포스터·연혁·장소·후원사·영상 썸네일 등 콘텐츠 사진은 **사진 저장·적용**을 누른다. 기존 콘텐츠의 사진 필드만 바뀌며 제목·본문·공개 여부는 유지된다.

고정사진의 **기본 사진으로 복원**도 초안 저장 후 게시해야 반영된다. 교체·복원 시 이전 업로드 파일을 삭제하지 않는다.

## 한글·영어

- 고정사진은 한·영 화면에서 같은 사진을 사용하고, 대체 설명은 각각 입력할 수 있다.
- 콘텐츠 카드의 **영어 사진**은 기존 영어 콘텐츠 저장소를 사용한다. 설정하지 않으면 원본 사진을 사용한다.
- 영어 사진 게시 RPC는 선택한 사진 필드만 게시한다. 게시된 번역 문구와 다른 미완성 문구 초안은 유지된다.
- 지휘자·반주자 프로필은 기존 데이터 구조에 맞춰 공통 사진을 사용한다.

## 범위와 안전

- 단원 개별사진, 입단지원 첨부사진, 접수 서명과 기타 개인정보는 관리 목록에서 제외한다.
- `site-images`는 공개 버킷이다. 아직 게시하지 않은 파일도 주소를 아는 사람은 열 수 있으므로 개인정보·비공개 자료를 업로드하지 않는다.
- 관리 권한은 기존 `profiles.role = 'admin'` 및 Storage RLS를 유지한다.
- 고정사진 저장·게시에는 버전 확인, 콘텐츠 사진에는 기존 사진 값 확인을 적용해 다른 관리자의 변경을 덮어쓰지 않는다.
- 업로드 실패·저장 실패 시 입력을 유지한다. 저장 전 페이지 이동·닫기에는 변경사항 경고가 표시된다.
- 인물·포스터의 기존 비율을 유지한다. 고정 사진의 중심 위치는 사진 요소에만 적용되며 원본 파일을 잘라 저장하지 않는다.
- 재생 프레임·아이콘·지도 iframe·영상 본체 등 기능 리소스는 사진 교체 대상이 아니다.

## 설치와 유지보수

두 additive migration이 필요하다. 기존 한국어/영어 편집 문서는 변경하지 않는다.

- `20260929224135_add_site_photo_overrides.sql`
- `20260929225757_publish_english_photo_without_copy_changes.sql`

현재 public 자산의 목록은 `src/features/site-photos/sitePhotoCatalog.ts`에 있다. 새 공개 사진 경로를 추가하면 이 목록에도 사용 위치를 등록한다. `sitePhotoCatalog.test.mjs`가 누락·중복과 기본 파일 존재 여부를 확인한다. 개발 샘플 fixture/seed와 관리자 빈 화면용 placeholder는 공개 사진 목록에 포함하지 않는다.

## 조사 근거

[2,000개 실제 사례 목록](research/site-photos/references-2000.json)과 [자동 분류 결과](research/site-photos/summary.json)를 기록했다. WordPress/Gutenberg 및 Strapi의 공개 이미지·미디어 이슈를 중복 URL 없이 수집하고 제목·본문의 키워드로 분류했다. **2,000개 디자인을 사람이 하나씩 상세 검토했다는 의미가 아니다.**

상세 구현 판단에는 다음 공식 자료를 사용했다.

- [Supabase 표준 업로드](https://supabase.com/docs/guides/storage/uploads/standard-uploads): 기존 파일 덮어쓰기 대신 새 경로를 사용해 캐시 회귀를 피한다.
- [Supabase Storage 접근 모델](https://supabase.com/docs/guides/storage/buckets/fundamentals): 공개 파일 읽기와 관리자 업로드 권한은 별도로 다룬다.
- [OWASP 파일 업로드 지침](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): 형식·확장자·파일 시그니처·크기·권한 검사를 재사용한다.
- [Sanity 이미지 모델](https://www.sanity.io/docs/studio/image-type): 원본 이미지와 사용 위치의 설명·중심 위치를 분리하는 방식을 참고한다.

배경 장식은 기존 의미 없는 이미지의 접근성 처리를 유지한다. 의미 있는 사진의 대체 설명은 해당 화면의 한국어/영어에 맞게 제공한다.
