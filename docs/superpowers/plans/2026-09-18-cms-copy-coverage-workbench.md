# CMS 문구 편집 범위 점검과 편의 도구

## Goal

공개 홈페이지의 문구 원천을 확인해 편집 누락과 키 충돌을 고치고, 비전문 관리자가 문구를 찾고 안전하게 바꾸도록 12개 이상의 실용 기능을 제공한다. 카탈로그 항목 수를 전체 편집 완료의 증거로 사용하지 않는다.

## Architecture

기존 SiteCopy/HomeCopy → SiteEditorProvider → 관리자 초안/게시 흐름을 유지한다. 정적 문구는 페이지·기기별 문서, 공연·인물·FAQ 등 데이터는 원래 CMS의 단일 원본으로 유지한다. 검색/치환은 일반 텍스트만 다루고 공개 화면 DOM을 임의 편집하지 않는다. 원문과 서식의 스냅샷을 비교한 뒤 하나의 로컬 초안 트랜잭션으로 적용한다.

## Tech stack

React 19, TypeScript, Vite, 기존 Node test runner, Supabase CMS. 새 production dependency 없음.

## Spec / global constraints

- 방문자 기본 디자인·문구·DOM 배치를 유지한다.
- 임시저장과 게시, 관리자 인증·권한·RLS·비공개 데이터 경계를 유지한다.
- 검색은 공개 문구 정의와 CMS 편집 초안만 대상으로 하며 접수함 개인정보는 인덱싱하지 않는다.
- 모든 바꾸기는 대상 페이지와 기기를 명시하고 자동 저장/게시하지 않는다.
- 실제 검증하지 않은 흐름은 미검증이라고 기록한다.
- 실제 운영 데이터에 테스트 내용을 저장하지 않는다.

## Tasks

### 1. 원천과 커버리지 감사

- `scripts/public-copy-contract*`, `siteCopy*Catalog`, 공통 메뉴, public route, HomeCopy projection, CMS content links를 대조한다.
- 중복 href의 서로 다른 메뉴 라벨을 독립 키로 분리한다. 기존 키/기본 렌더링 호환성을 유지한다.
- 아직 화면 직접 선택이 불가능한 문구와 전용 CMS 원문/이미지 내 텍스트/자동 계산 값을 구분한다.
- 실패하는 contract/behavior test를 먼저 실행한 뒤 수정·재검증한다.

### 2. 공식 문서 조사와 Figma 보강

- Microsoft/Hancom 편집기, W3C 검색 결과 안내·키보드·오류 복구, 웹 편집기 문서를 확인한다.
- 확인한 출처 수와 채택/제외 이유를 기록한다. 요청하지 않은 대규모 건수를 주장하지 않는다.
- 기존 691:2711 시안을 보존하고 찾기·바꾸기 패널을 추가 제작한다.

### 3. 검색·치환 모델 — 테스트 먼저

새 `editorCopyTools.ts`와 실제 모듈 테스트:

- 대소문자·완전한 단어·유니코드 글자 경계를 보존한 literal 검색.
- 원문/기기 상속 해석, 미저장/재정의/빈 문구/공백 점검, 문자·단어·줄 통계.
- 한 위치 치환과 선택 항목 일괄 치환 계획, 변경 전후·발생 횟수·제외 사유.
- URL/숫자/표시 설정은 일괄 문구 치환에서 제외.
- HTML, 최대 길이, 잘못된 위치, 오래된 초안/서식, 기기 불일치 거부.
- 해당 위치의 기존 글자 서식 유지, 다른 페이지·기기·문구 불변.

### 4. 편의 기능 UI

기존 CMS 토큰과 44px 조작 영역으로 다음 신규 기능을 연결한다. 기존에 있던 단순 목록 검색/글자 수/되돌리기 버튼은 신규 개수로 세지 않는다.

1. 전체 페이지의 저장 초안과 현재 미저장 입력을 찾는 통합 검색.
2. 검색어가 표시되는 결과 강조와 출현 횟수.
3. 결과 이전/다음 이동 및 현재 순서.
4. 대소문자·완전한 단어 검색 옵션.
5. 선택 문구 안의 일치 위치 한 건 바꾸기.
6. 대상 체크·변경 전후 미리보기를 거치는 일괄 바꾸기.
7. 미저장 변경 문구만 보기.
8. 현재 기기 재정의/상속 문구 구분 필터.
9. 즐겨찾기(문구 키만 이 브라우저에 보관).
10. 최근 편집 목록(키만 세션에 보관).
11. 원문/임시저장본/현재 입력 비교.
12. 모바일·태블릿·데스크톱 값 나란히 비교.
13. 서식 없이 문구 복사와 실패 피드백.
14. 빈 문구·이상 공백·길이 초과 점검 필터.
15. 문구 목록/일괄 변경을 포함한 문서 단위 실행 취소·다시 실행.
16. 찾기 단축키와 화면 내 도움말.

필요한 API: `EditorCopyPanel`에 baseline, bulk-apply callback; `AdminSiteEditorPage`에 원자적 edit/history 연결. 전체 검색은 실패 페이지를 표시하며 확인하지 못한 값으로 편집하지 않는다.

### 5. 회귀 검증

- 각 모델 테스트 RED → GREEN 기록. 선택 중 검색 결과 재계산으로 입력창이 사라지지 않게 한다.
- `pnpm lint`, `pnpm test`, `pnpm build`.
- 격리된 실제 App fixture에서 검색·치환·취소·되돌리기·저장·재접속, 오류·키보드·390/768/1440 확인.
- public route overflow, 기본 디자인 변화/편집 DOM 노출 없음 확인.
- 실제 DB 테스트 데이터 생성 없이 fixture 종료, diff 확인 후 commit/push.

## Completion evidence

### 실제 반영 — 2026-09-18

- [원문 연결 감사](../../site-editor-copy-coverage.md): 기존 1,097 → 1,247개 고유 키, 이번 150개 추가. 직접 JSX/조건문 검사·실제 원문 소비·SSR 기본 출력 보존을 구분했다. **전체 문자열 100% 편집 완료가 아니다.**
- [공식 자료 조사와 Figma 시안](../../research/2026-09-18-cms-copy-workbench.md): 새 공식 본문 14개, Figma 시안 6개. 사용자 인터뷰나 수만 건 조사를 했다고 주장하지 않는다.
- 홈의 단일 정규화 문구를 실제 화면 편집에 연결했다. 여러 원문을 합친 문구는 원문 목록으로 안내하며 임의로 한 필드에 합쳐 저장하지 않는다.
- Auth/RLS/API/테이블/마이그레이션 변경 없음. 공개 홈페이지 기본 디자인·사진·원문은 유지했다. 관리자 CSS에만 편의 도구 스타일을 추가했다.

### 신규 편의 기능 — 중복 없이 15개

| 기능 | 실제 구현 및 확인 |
|---|---|
| 전체 페이지 문구 검색 | 15개 페이지 초안 읽기, 현재 미저장 입력 보존, 실패 페이지 제외·재시도, 결과에서 페이지·기기·필드로 이동 |
| 대소문자/완전한 단어 검색 | 한국어·영어·이모지·결합문자 경계 테스트, 정규식 해석 없음 |
| 검색 강조와 이전/다음 결과 | 결과 문구 수와 본문 일치 수 구분, 현재 순서·선택 표시 |
| 현재 문구의 한 위치 바꾸기 | 이전/다음 일치 위치, 문맥 미리보기, 해당 offset만 치환 |
| 선택 항목 일괄 바꾸기 | 변경 전후·기기 확인, 체크한 항목만 하나의 로컬 트랜잭션으로 적용 |
| 임시저장 전 변경만 보기 | 텍스트와 부분 서식 변경 포함 |
| 재정의/상속 상태 필터 | 현재 범위에서 수정한 값과 원문·공통값 구분 |
| 즐겨찾기 | 브라우저에 키만 저장, 해제·저장 불가 안내 |
| 최근 편집 | 현재 탭에 키만 저장, 일괄 편집의 모든 대상 포함 |
| 원문·저장본·현재 입력 비교 | 값이 비어 있으면 빈 문구라고 표시, 원본으로 추측해 채우지 않음 |
| 기기별 값 비교 | 모바일/태블릿/데스크톱 및 홈 native sourceKey 대응 |
| 서식 없는 문구 복사 | Clipboard 성공·실패 안내 |
| 빈 문구·공백·길이 점검 | 자동 수정 없이 확인 권장 필터/안내 |
| 목록·일괄 변경 문서 undo/redo | 한번에 복구, 뒤의 변경/서버 갱신 보호, IME 조합 1회 undo |
| 전체 찾기 단축키와 도움말 | CMS에서 Ctrl/⌘+Shift+F, 조합 중 가로채지 않음, 모달 Esc 닫기·포커스 복귀 |

기존 글꼴·크기·색상/기본 복원/단순 글자 수/위치 필터는 이미 존재했던 기능이라 신규 개수에서 제외했다.

### 검증 결과

- `pnpm test`: 559개 중 **557 통과 / 0 실패 / 2 skipped**, 94.8초. 새 테스트 파일 4개를 정규 test runner에 등록했다.
- `pnpm build`: TypeScript 및 Vite production build 통과(822 modules).
- `pnpm lint`: 통과. `git diff --check`: 오류 없음.
- 모델/컴포넌트 재현 후 수정: 메뉴 키 충돌, 조건부 문구 누락, 반복 문자열 offset, 결합문자 서식 침범, stale 일괄 치환, IME undo·취소·동시 갱신, inherited 서식 지우기.
- 실제 App을 사용하는 **5177 격리 fixture** 브라우저: 17개 치환 후보 중 1개만 선택, 초안 반영, undo/redo, 변경 필터, 즐겨찾기, 기기 비교, 평문 복사, 전체 검색 15/15, 다른 페이지로 이동 후 미저장 입력 재검색, 임시저장·재접속 확인.
- 공통 메뉴의 별도 라벨 편집과 화면 직접 편집, 홈 정규화 소개 문구 입력→마침→문서 undo, 찾기 단축키, Esc 모달 닫기 후 버튼 포커스 복귀 확인.
- 모바일 390px 문구 도구/검색 모달 실측·스크린샷 확인. 768px 모달 경계/overflow 확인, 데스크톱 검토 모달 확인. 일부 태블릿 캡처는 브라우저 캡처의 타일 중복이 있어 시각 증거로 사용하지 않고 DOM 경계만 근거로 삼았다.
- **5175 공개 서버**: `/`, `/spirit`, `/about?section=spirit`, `/about?section=conductor`, `/about?section=accompanist`, `/about?section=members`, `/join`, `/contact?section=support`의 실제 h1 렌더 완료 후 390/768/1440px 총 24조합 확인. 가로 overflow 0, 편집용 `smyc-edit-target` 0, Vite error overlay 0. 공개/격리 CMS 브라우저 console error 각각 0.
- 첫 route 검사는 로딩 화면까지 포함해 증거로 채택하지 않았다. 이후 h1·본문 렌더를 기다리는 검사로 모두 다시 확인했다.
- 운영 데이터 쓰기·게시 없음. fixture는 외부 연결 차단/productionRequests 0 확인 후 종료했다. 검증용 즐겨찾기 해제, QA 탭 2개 닫기, viewport override 초기화. 실제 5175 개발 서버는 유지했다.

### 남은 제한

- 동적 접근성 문장 suffix, 날짜·수량 템플릿, 일부 공통 fallback/전역 SEO/서버 검증 오류는 아직 코드 원문이다. 정확한 예는 연결 감사 문서에 기재했다.
- 공연·인물·FAQ·약정 본문은 기존 전용 CMS가 원본이다. 통합 검색은 고정 문구 카탈로그와 초안만 검색하며 접수함의 개인정보는 읽지 않는다.
- OS 한글 IME와 실제 iOS/Android 가상키보드 검증은 미수행. 조합 이벤트/상태·undo는 실제 모듈 테스트로 확인했으며 일반 한국어 입력은 브라우저에서 확인했다.
- 전체 페이지 일괄 치환은 지원하지 않는다. 현재 페이지·명시한 기기로 한정해 부분 성공/다른 기기 오변경을 피한다.
- 등록된 모든 키를 실제 운영 DB에 저장·게시하며 전수 시험하지 않았다. 키 수는 그러한 E2E 보장을 뜻하지 않는다.
