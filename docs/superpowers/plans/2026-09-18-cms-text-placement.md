# CMS 문구 자동 크기·배치 편집 실행 계획

## Goal

문구 입력량에 따라 선택 테두리가 실제 영역을 따라가고, 관리자 미리보기에서 문구 블록의 위치·너비·정렬을 기기별 초안으로 수정한다. 기본 공개 홈페이지의 DOM·서식·배치는 보존한다.

## Architecture / Tech stack

React / TypeScript / Vite / Supabase JSON 문서. 기존 copy/textStyles와 별도의 `textLayouts[device][stableBlockId]`를 사용한다. React useId, DOM 경로, 문구 내용은 영구 식별자로 사용하지 않는다. 명시적인 블록 카탈로그만 이동 가능하다. 전체 제목이나 문단은 한 블록으로 취급해 여러 문구 조각을 따로 이동시키지 않는다.

## Global constraints / specification

- 공개 기본값: 레이아웃 값이 없으면 원래 자식 요소를 그대로 반환. 공개 화면에 편집용 wrapper/handle 미노출.
- 문구: 폰트를 자동 축소하지 않고 줄바꿈과 높이 증가. 인라인은 가용폭까지 자동 증가하며 기존 중심/오른쪽 기준을 보존.
- 배치: 원래 위치 대비 X/Y(px), 너비(%), 문단 start/center/end. 높이는 저장하지 않는다.
- 정렬: 같은 그룹의 다른 블록을 기준으로 선택 블록 한 개의 가로 또는 세로 중심을 맞춤. 지속적인 제약 관계가 아닌 현재 배치 명령임을 안내.
- 이동: 별도 배치 모드와 이동 손잡이. 텍스트 드래그 선택과 충돌하지 않는다. pointerup 1회 기록, Esc/pointercancel 취소, 숫자/방향 버튼 대안.
- 안전: nonce/origin/source/page/sequence 검증, 부모의 신뢰된 초안 기준 CAS, 중복/지연 메시지 방어. 이동 중 다른 페이지/기기/게시 조작 잠금.
- 저장: 데스크톱·태블릿·모바일 독립. 기존 임시저장→미리보기→게시, undo/redo·복원·충돌 흐름에 포함. 공통 서식 범위에는 배치값을 저장하지 않는다.
- 데이터: SQL 검증 함수만 확장. Auth/RLS/기존 데이터와 제출 기능 미변경. 실데이터로 테스트 게시하지 않는다. 이전 클라이언트는 새 필드를 거부하므로 새 앱 배포 전 실서비스 배치 게시 금지.
- 범위: 명시 등록한 제목·소개·문단 블록. 메뉴/폼 컨트롤/개별 글자나 반복 데이터 행의 임의 이동은 허용하지 않는다.

## Tasks (RED → GREEN → verification)

1. 기존 runtime 크기 측정 실패 재현 → 입력·서식·undo·resize의 live bounds 테스트 → auto-grow 수정.
2. 배치 스키마·세션·undo·미리보기 검사 RED → 제한값 검증/patch/reconcile/restore와 SQL validator 추가.
3. 명시 카탈로그와 no-op 공개 renderer 테스트 RED → 원래 native 요소 clone, 기기별 안전한 스타일 적용.
4. iframe 배치 프로토콜/gesture 모델 RED → 부모 grant/CAS, 이동·취소·스냅·키보드, 정리.
5. CMS 패널·페이지 통합 → 숫자 입력/너비/중심 맞춤/원래 배치/초안 피드백.
6. Figma 별도 샘플·공식 문서 조사 → 4가지 상태(기본/패널/겹침/범위 제한) 확인.
7. 통합 회귀: 단위 테스트, 타입, lint, build. 격리 fixture에서 긴 문구·이동·정렬·undo/redo·기기 변경·임시저장·재로드.
8. 390/768/1440 기본 공개 화면과 편집 화면 확인. 테스트 데이터·임시 탭 정리. 검증 증거/제약 기록 후 커밋.

## Acceptance evidence

### 구현·검증 결과

- 12개 화면, 30개 명시적 문구 블록 등록. 홈의 모바일/태블릿/데스크톱 구현은 같은 안정 ID를 사용하며 실제 표시 중인 하나만 등록한다. 역사 compact/full 분기도 동일 원칙이다.
- 공지 제목 실브라우저 입력 검증: overlay 높이 91.2 → 431.2px, 문구 축소 후 91.2px. 표시 테두리도 새 글자 영역을 포함했다. 폰트를 자동 축소하지 않았다.
- 격리된 실제 앱(127.0.0.1:5177)에서 X=24/Y=12 적용 → 임시저장 → 재로드 값 유지 확인.
- 다른 문구의 상하 중심 맞춤: 두 실제 DOM 중심 Y=317px 일치. undo로 Y=12, redo로 Y=92.5 복귀 확인.
- 마우스 드래그 결과 X=122.3/Y=86.3 유지. Shift+오른쪽 키로 X=132.3, 한 번 undo로 122.3 복귀. 이동 중 Esc 취소 후 값 불변.
- 모바일 X=10과 태블릿 너비 50%/가운데 정렬을 각각 설정. 다른 기기의 값이 섞이지 않음을 확인했다.
- 새 숫자 입력 중 화면/기기/저장 버튼 잠김, 숫자 적용 버튼 활성. 입력 취소 시 잠금 해제와 이전 값 복원 확인.
- 폭 50%에서 X=1000 적용 후 폭 100%로 확장: 저장 X=1000과 표시 X=700.5가 구분됨. 이후 다른 문구에 좌우 중심 맞춤 결과 두 실제 DOM 중심 X=404.15px 일치. 저장값에 잘못된 보정량을 누적하지 않는다.
- 격리 fixture에서 기기별 변경 내역을 사람용 라벨로 확인하고 모의 게시. 태블릿 공개 렌더러는 너비 50%/가운데 정렬을 표시하면서 편집 marker/overlay=0, 가로 초과=0.
- 390px CMS: 문서 가로 초과 0, 배치 패널 폭343.2px/높이337.6px, 44px 미만 배치 버튼 0개. 실제 모바일 하드웨어/iOS Safari는 미검증.
- `pnpm test`: 668개 중 666 통과, 실패0, 선택형 브라우저 테스트2 skip (100.6초). 이 스킵을 성공으로 계산하지 않았다. 대신 위 CUA 통합 검증을 별도로 수행했다.
- `pnpm lint`, `pnpm build`, `git diff --check` 통과. 공개 JSX 기본값/SSR 동등성 계약은 유지되고 baseline 파일은 갱신하지 않았다.
- 공개 12경로 × 390/768/1440 총 36조합에서 가로 초과/편집 표시/Vite overlay 모두0, 수집된 console warn/error0. [실제 측정 표](../../research/2026-09-18-cms-text-placement.md#9-공개-홈페이지-브라우저-회귀-검증)는 별도 기록했다. 픽셀 단위 전후 이미지 비교는 아니며 기존 `/sample` 공연 링크는 미변경 사항으로 구분했다.
- 운영 DB는 [검증 함수만 적용](../../deployments/2026-09-18-site-editor-layout-validator.md). 기존 콘텐츠·Auth·RLS 불변, 운영 콘텐츠 테스트 저장/게시0.
- 검증용 5177 프로세스를 종료해 그 프로세스 메모리에 생성했던 임시저장·모의 게시 레코드를 정리했다. 원래 5175 서버는 HTTP200으로 유지했다. 검증용 브라우저 탭과 per-tab 화면 크기 설정도 정리했다.

### 범위와 사용 방법

CMS → 홈페이지 편집 → 화면과 기기 선택 → **배치 조정** → 문구 선택 → 손잡이/숫자/방향 버튼/중심 맞춤 → 임시저장 → 게시 순서다. 텍스트 수정은 별도의 **화면에서 편집** 모드다. 문구·글꼴을 유지하고 배치만 원래대로 돌리는 버튼도 제공한다.

자동 확장은 편집 대상 글자 영역을 따라간다. 블록 높이는 저장하지 않고 본문 길이에 맡긴다. 너비 자동은 원래 반응형 폭을 복원하는 동작이며, 모든 블록을 무조건 한 줄로 늘리는 뜻이 아니다.

다른 문구와 중심 맞춤은 현재 시점의 정렬 명령이고, 이후에도 두 문구를 영구 연결하는 제약 관계는 아니다. 길이나 서식이 바뀌면 다시 맞출 수 있다. 마우스 이동 시 같은 그룹 중심에 가까워지면 안내선과 스냅을 제공한다.

메뉴/입력폼/반복 데이터 행/임의 DOM 요소는 이동 대상으로 만들지 않았다. 안전한 의미 단위 블록만 선택 목록에 표시한다. 겹침은 경고하고, 화면/섹션 밖 이동은 제한한다. 기존 공개 디자인을 자동 정렬하거나 재배치하지 않는다.

### 이번 검토에서 찾아 고친 경계 사례

1. 글자 증가 후 고정 테두리, 2. 인라인 중심/오른쪽 기준 상실, 3. 성공 ACK 뒤 옛 translate 덮어쓰기, 4. 숨긴 반응형 중복이 실제 블록을 지우던 문제, 5. 중심 스냅에 갇힌 1px 키보드 이동, 6. grant 응답 누락 복구, 7. pointercancel/Esc 대기 중 경합, 8. 텍스트 편집과 배치의 freeze 경합, 9. Undo 시 옛 숫자 초안 재등장, 10. 선택 왕복 시 미적용 숫자 재등장, 11. 화면 이동 시 미적용 숫자 소실, 12. 표시 경계 제한 후 정렬 기준 오차, 13. 지연 데이터 DOM 등록, 14. 글꼴/크기 변경 후 측정 갱신 및 관찰기 정리.

새 라이브러리, 운영 테스트 레코드, 전역 스크롤바 스타일, 영어 번역 기능은 추가하지 않았다.
