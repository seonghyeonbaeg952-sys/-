# 원본문구 기반 Figma 샘플과 CMS 초안 적용 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan. Steps use existing CMS draft/publication separation; no automatic publishing.

**Goal:** 사용자 첨부 텍스트의 22개 항목을 현재 홈페이지 디자인에 맞춰 Figma에 먼저 검증하고 CMS 초안으로 적용한다.

**Architecture:** PDF는 원본문구 확인용으로만 사용한다. 색상·글꼴·사진·레이아웃 디자인은 현재 홈페이지와 기존 Figma 캡처를 따른다. 기존 site_editor_pages의 copy/deviceCopy를 사용하고, 연결되지 않은 설명문만 기존 SiteCopy 패턴으로 연결한다. 문구를 앱 소스에 새 기본값으로 하드코딩하지 않는다.

**Tech Stack:** React / TypeScript / Vite / Supabase / Figma.

## 변경 경계

- 대상: 홈 소개·입단·공연·기록·교육철학·후원, SPIRIT 전체 문구.
- 유지: 홈 대표 제목, 선언문 제목, 공동체 제목, 사진, 포스터, 영문 장식, 연도, 성경 말씀과 출처, URL과 인터랙션.
- 선택 문안은 첨부에서 마지막으로 권장한 안을 사용한다. 메뉴 명칭 및 ‘섬기기 → 나누기’는 선택 제안이므로 이번 필수 교체와 분리하고 기존 이름을 유지한다.
- 기존 모바일 홈 제목 초안은 변경 범위가 아니므로 그대로 보존한다.
- CMS 임시저장만 수행한다. published와 published_at은 바꾸지 않는다.
- Figma에 없는 캡처 글꼴은 샘플 한정 대체임을 명시한다. 홈페이지 폰트는 변경하지 않는다.

## Task 1 — 근거와 교체표

1. PDF의 원본문구와 첨부 텍스트 교체안을 섹션별로 대응시킨다.
2. 현재 CMS 문서와 관련 공개 데이터 원본을 백업한다.
3. 변경 목록은 key / 원문 / 교체문 / 기기 / PDF쪽 / 유지·선택 여부로 기록한다.
4. 공개 디자인 속성은 변경 목록에 포함하지 않는다.

## Task 2 — Figma 문구 적용 샘플

1. 현재 홈페이지 캡처를 복제해 새 ‘문구 개정’ 페이지에 배치한다.
2. 데스크톱·태블릿·모바일 홈/SPIRIT과 탭별 문구를 확인한다.
3. 현재 텍스트 폭, 사진과 여백을 유지하며 문단 길이에 맞춰 높이를 늘린다.
4. 문장 잘림·겹침·불필요한 강제 줄바꿈을 스크린샷으로 확인하고 수정한다.
5. PDF 사진·배경·레이아웃은 가져오지 않는다.

## Task 3 — 빠진 CMS 연결 보완

1. 원문 기본값이 그대로 렌더링되는 테스트를 먼저 만든다.
2. hero/body, 모테트 설명, 선언문 본문, 가치 탭, 홈 교육철학 상세 중 연결 없는 필드만 명시적인 키로 연결한다.
3. 기존 콘텐츠 데이터가 기본값이고 초안 override는 미리보기에서만 반영되어야 한다.
4. 연결별 override·기기 독립성·서식 없는 원문 보존을 검증한다.

## Task 4 — CMS 초안 저장

1. 교체표의 키가 실제 소비되는지 확인하고 문서 validator를 통과시킨다.
2. 기존 copy/deviceCopy/appearance/textStyles/textLayouts를 보존하며 문구만 병합한다.
3. 기대 버전으로 충돌을 막고 저장한다. 공개 데이터 직접 수정은 하지 않는다.
4. 저장 후 재조회하여 모든 문구, 버전, 기존 초안과 게시 상태 보존을 확인한다.

## Task 5 — 재검증과 인계

1. 타입·lint·관련 테스트·전체 테스트·build 실행.
2. 관리자 초안 미리보기와 공개 화면을 구분하여 확인.
3. 390 / 768 / 1440px에서 제목과 긴 본문의 가로 overflow·잘림을 확인.
4. 게시하지 않은 상태와 Figma 링크, 교체표, 남은 제한을 보고한다.
5. 이번에 생성한 임시 PDF 렌더만 정확한 경로로 정리한다. 사용자 데이터는 삭제하지 않는다.
