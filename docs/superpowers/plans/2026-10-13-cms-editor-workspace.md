# CMS 홈페이지 문구 편집 작업 공간

**Goal:** 기존 문구 편집 엔진과 저장 데이터를 유지하면서, 캔버스·문구 도구·선택 속성이 구분되는 실용적인 작업 화면을 구현한다.
**Architecture:** `AdminSiteEditorPage`의 세션/저장/게시/실행 취소 로직은 유지한다. 기존 `EditorPreview`와 `EditorWorkSurface`의 UI 계층만 재구성하고, 문구 목록·전체 서식·이력은 접이식 도구 영역에 유지한다.
**Tech Stack:** React 19, TypeScript 6, Vite 8, 기존 CSS, Node test runner. 새 production dependency 없음.
**Spec:** 사용자의 CMS 문구 편집 UI 개선 요청 및 `docs/qa/2026-10-13-cms-editor-ui-comparison.md`의 40개 공식 사례 비교.

## 범위 / 전역 제약

- 복구 기준: 시작 시 깨끗한 `main`, `2a6ba8b518ccc74b24e59f81492febe434190e20`.
- 방문자 페이지·Spirit 연출·실제 문구·초안·서식 데이터·DB schema·Auth/RLS를 변경하지 않는다.
- 한글/영어 독립 세션, IME 입력 잠금, 미적용 배치 입력 잠금, 충돌 처리, 저장/게시 분리를 보존한다.
- 기존 Motet 관리자 토큰과 Carbon 라이선스 아이콘을 사용한다. Figma kit 전체를 이식했다고 주장하지 않는다.
- 단일 화면/기기 선택, 44px 조작 영역, 이름 있는 버튼, 보이는 focus, 접이식 영역의 상태를 유지한다.
- 코드 주도 기존 관리자 디자인 확장이다. 새로운 브랜드 세계나 이미지 생성, CMS 전체 개편은 제외한다.

## 디자인 계약

THESIS: 긴 안내와 도구가 작업 화면을 밀어내는 구조를 짧은 문맥 도구와 캔버스 중심 구조로 바꾼다.
OWN-WORLD: 기존 아이보리/흰 컨트롤/버건디 선택색, 4px 모서리, Gothic A1 UI 서체, Carbon 아이콘.
STORY: 화면·적용 기기를 고른다 → 캔버스에서 문구 선택 → 오른쪽 속성 조절 → 임시저장 → 변경 확인 후 별도 게시.
FIRST VIEWPORT: 짧은 제목/언어 선택, 한 줄 문맥 선택, 작업 명령, 캔버스와 오른쪽 속성. 저장 상태와 게시 버튼은 하단 유지.
FORM: 기존 CMS 작업 공간의 확장. 코드 주도; 개별 문구 속성과 페이지 전체 도구를 분리한다.

## 파일 책임

- `src/components/admin/site-editor/EditorPlacementToolbar.tsx`: 문구 속성의 위치/문단/고급 조작 그룹. 검증/commit 엔진 유지.
- `src/styles/admin-site-editor-workspace.css`: CMS에만 적용되는 일관된 작업 공간 스타일.

## 자체 검토

- 새 문구 에디터/프레임워크를 도입하는 대신 기존 브리지·세션을 그대로 사용하므로 DB 문구/서식 호환성을 유지한다.
- 접기 상태 때문에 입력이 unmount되지 않도록 컴포넌트는 유지하고 `hidden`을 사용한다. 숨기는 동안 편집 중이면 접기를 막는다.
- 디자인 수정은 문서/화면 소스 상태와 별개다. 저장·게시 회귀 테스트를 UI 검사보다 먼저 수행한다.
- 브라우저 스크린샷 실패 시 성공으로 기록하지 않는다. 문서화된 브라우저 기능으로 해결 가능한지 확인하고 남은 제한을 명시한다.

## 실행 중 발견한 회귀와 검증

- 새 최대 높이 때문에 1440×720px 맞춤 화면에서 세로 스크롤바가 나타났다 사라지며 가용 폭이 806/790px로 번갈아 바뀜. 수정 전 120프레임 중 배율 전환 119회.
- `scrollbar-gutter: stable`과 미지원 브라우저의 `overflow-y: scroll`로 크기 피드백을 차단. 최종 코드의 10조건(높이 690/700/710/720/740px, 모바일/태블릿/데스크톱 맞춤, 실제 크기, 공개본)×120프레임에서 폭·높이·배율 전환 모두 0.
- 실제 브라우저 회귀 함수는 `EditorPreview.browser-fixture.mjs`에 있다. 렌더링된 CMS의 DOM에서 허용된 브라우저 도구로 `assertStableEditorPreview`를 평가한다. DOM 없는 `pnpm test`에 자동 포함된 테스트라고 주장하지 않는다.
- 찾기 모달을 열면 메뉴가 닫혀 복귀 버튼이 숨겨지는 포커스 회귀를 red→green 테스트로 수정. 모달의 Escape는 모달에 맡기며, 닫으면 보이는 버튼으로 복귀하고 두 번째 Escape는 메뉴 summary로 복귀.
- 문서 도구 닫기도 보이는 작업 버튼에 `preventScroll` 포커스를 돌려준다. 양 언어의 미적용 숫자 입력은 테스트 중 적용/저장/게시하지 않았다.
- 첫 전체 실행은 1196 통과/11 skip. 포커스 회귀 추가 후 두 번째 실행은 1200 통과/11 skip/사진 테스트 파일 프로세스 1실패. 해당 파일 단독 테스트 3개는 통과했다. 테스트를 제거하거나 실패를 무시하지 않고 다시 실행한 최종 전체 검증은 1200 통과/11 skip/실패 0 (192초). 간헐적인 테스트 프로세스 종료의 근본 원인을 해결했다고 주장하지 않는다.
- Chrome의 캡처 API가 시간 초과여서 성공 증거로 사용하지 않았다. 인증된 IAB에서 실제 CMS 여섯 화면을 캡처했다. 독립 검수자는 화면과 코드를 검토했으며 저장/게시를 대신 수행하지 않았다. 물리적 모바일 기기 검증은 미수행.
