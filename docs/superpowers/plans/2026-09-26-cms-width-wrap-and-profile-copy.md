# CMS 문구 상자 너비·줄바꿈·독립 편집 복구

## 안전 조건

- 기존 미커밋 작업과 저장된 초안을 보존한다. 검사용 변경은 실행 취소하며 게시하지 않는다.
- 기본 public DOM, 원래 강제 개행, 사진, 폰트와 디자인은 변경하지 않는다.
- 너비 직접 설정만 자동 줄바꿈을 활성화한다. 저장값의 백분율 기준은 그대로 유지한다.
- 인증, RLS, 편집 권한, 버전 CAS 검증은 그대로 유지한다.

## 확인한 원인

1. 상자 너비가 클라이언트·DB 모두 100%로 제한된다. 손잡이도 부모 폭으로 잘라 원래 폭 이상 확장이 불가능하다.
2. 홈페이지 제목의 내부 강조 span이 `white-space: nowrap` + inline-block이라 좁힌 상자 밖으로 글자가 넘친다.
3. 반주자 프로필 반복 렌더링이 동일한 원문 키를 사용한다. 발생 위치가 아니라 안정적인 프로필 ID별 편집 키가 필요하다.
4. 새 문구/반주자 문구의 글꼴 편집은 실제 브라우저에서 선택 → 권한 부여 → 플로팅창 → 서식 반영까지 확인해야 한다.

## 실행 순서

### 1. 너비 계약과 회귀 테스트

- 기존 10–100% 값의 의미 유지. 10–400%로 범위 확장, 실제 화면·섹션 경계에서 제한.
- 실제 CSS containing block의 content 폭을 측정하여 inline 부모 및 축소된 제목의 좌표를 처리.
- 드래그/숫자 입력/프로토콜/문서 유효성/DB 검증의 범위를 일치시킨다.
- 확장, 축소, 과도한 확장, 취소, 되돌리기 테스트를 먼저 실패시킨다.

### 2. 수동 너비에서만 줄바꿈

- 직접 조절한 상자에만 scoped 표식을 달고 내부 텍스트의 nowrap을 해제한다.
- 원래 개행 요소와 타이포그래피를 유지한다. 높이는 내용에 따라 자동 증가한다.
- 반응형 경계 제한을 공통 renderer hook으로 처리한다.
- 편집 오버레이도 지정된 상자 너비를 따라가게 한다.

### 3. 프로필별 독립 원문

- 프로필 UUID와 라벨 종류로 독립 편집 키를 생성한다. 정렬 변경에도 해당 인물의 편집을 유지한다.
- 기존 공통 원문/서식은 독립값이 없는 동안 기본값으로 보존한다.
- 제한된 동적 키만 controller에서 인증하고 source/문구/서식 CAS를 유지한다.
- 실제 사용자 흐름에서 위·아래 독립 편집과 글꼴 플로팅창을 확인한다.

### 4. DB와 종합 검증

- CLI로 migration 파일 생성. 너비 validator 함수 범위만 확장, 기존 권한 유지.
- DB 검증 계약 실행(내용 데이터 생성/게시 없음).
- `pnpm lint`, `pnpm test`, `pnpm build` 실행.
- 실제 브라우저에서 확장/축소/자동 개행/서식/새 문구/실행 취소를 확인한다.
- 모바일 390px, 태블릿 768px, 데스크톱 1440px에서 기본 화면과 overflow 확인.
- 결과와 남은 한계를 사실대로 보고한다.

### 5. 추가 상자 편집 시 테두리 급확대 회귀

- 브라우저 재현: 짧은 새 문구를 편집하면 부모 문단의 약 1,424px가 최소 너비로 적용됨.
- 새 상자는 문단 전체가 아닌 독립 객체로 취급. 기본 폭은 내용 기준으로 측정하고, 명시적으로 지정한 폭은 유지.
- 기존 제목과 강제 개행은 변경하지 않는다. 편집 시작/입력 증가·감소/편집 마침/이동·너비 손잡이 전환을 검증.
- 테스트 문구는 저장·게시하지 않고 실행 취소한다.

검증 기록:

- 브라우저에서 짧은 추가 문구의 편집 시작 시 폭 약 1,424px / 최소 너비 1,424.2px가 적용되는 것을 직접 측정했다.
- 수정 전 동일한 런타임 회귀 테스트가 `640px !== 44px`로 실패했고, 수정 후 관련 78개 테스트가 통과했다.
- `pnpm test`: 731개 중 729개 통과, 2개 브라우저 의존 테스트 건너뜀, 실패 0. `pnpm lint`와 `pnpm build` 통과.
- 수정 후 직접 화면 재검증은 브라우저 연결 끊김으로 완료하지 못했다. 모바일/태블릿 실제 화면 검증도 완료로 간주하지 않는다.
- 검증 문구는 관리자 메모리 초안에만 생성했다. 저장·게시/DB 테스트 데이터 생성은 하지 않았다. 기존 저장된 초안은 유지했다.
