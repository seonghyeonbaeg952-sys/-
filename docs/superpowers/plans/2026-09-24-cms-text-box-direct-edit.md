# CMS 문구 상자 직접 편집 및 공개 문구 감사

## 목표와 경계

- 관리자 미리보기에서 텍스트를 선택해도 기존 한 줄 제목이 조기 줄바꿈되지 않게 한다.
- 배치 모드에서 선택한 문구 상자의 가장자리를 직접 잡아 너비를 조절한다. 기존 숫자 입력과 키보드 이동은 대체 조작으로 유지한다.
- PowerPoint처럼 각각의 문구 상자가 독립적인 선택·이동·편집 대상을 갖도록 한다. 선택한 상자를 유지한 채 글자 편집과 위치·너비 조절을 오갈 수 있어야 한다.
- 관리자가 새 문구 상자를 만들 수 있도록 별도 텍스트 원본, 고유 ID, 배치, 초안/게시 상태를 설계한다. 새 상자는 공개 페이지의 기존 DOM을 덮어쓰거나 임의 HTML을 허용하지 않는다.
- 긴 편집 문구가 옆 요소를 가리지 않도록 실제 배치 제약과 편집 중 reflow를 검증한다. 모바일에서 공간이 부족하면 자연스러운 줄바꿈을 허용하되, 기존 상자 폭 때문에 조기에 꺾이지 않아야 한다.
- 변경은 기기별 초안에만 반영하고, 게시 전 공개 홈페이지의 기본 레이아웃은 그대로 둔다.
- 모든 공개 문구의 소유권을 점검한다. 고정 문구는 문구 카탈로그, 공연·인물·모집 등 동적 원문은 전용 CMS에서 편집하도록 유지한다. 입력값·개인정보·보안 오류를 무분별하게 공개 문구 override에 섞지 않는다.

## 구현 순서

1. TDD로 한 줄 제목 편집 상자의 자동 폭과 명시적 줄바꿈 보존을 재현한다.
2. 선택 테두리에 이동 및 너비 조절 손잡이를 붙이고, grant/commit/cancel/undo 경계를 기존 프로토콜로 유지한다.
3. 손잡이 드래그는 현재 기기의 너비 값으로만 저장한다. 반응형 화면 밖으로 밀리지 않도록 동일한 뷰포트·섹션 경계를 적용한다.
4. 상자 ID와 원문 소유권을 정리해 편집/배치를 한 선택으로 묶는다. 동적 공연·공지·인물 원문은 전용 CMS 단일 원본에 연결한다.
5. 새 상자 데이터 모델, 검증, 렌더링, 초안·게시, 기기별 배치, 키보드·드래그 조작을 추가한다. 기존 문서와 공개 페이지는 데이터가 없으면 동일하게 유지한다.
6. 공개 문자열 검사 스크립트와 화면별 CMS 원본을 대조해 빠진 고정 문구를 연결하고, 실제로 연결하지 않은 범위를 문서에 남긴다.
7. 단위 테스트, 린트, 빌드, 5175 실행 및 데스크톱/태블릿/모바일 미리보기 회귀를 확인한다.

## 조사 근거

- Microsoft PowerPoint 공식 문서의 `삽입 → 텍스트 상자 → 슬라이드 클릭 → 입력`, 개체 선택과 Enter로 텍스트 편집, 크기 조절 핸들, 방향키와 선택 창을 상호작용 기준으로 삼는다. 웹 CMS가 슬라이드 앱과 동일한 기능 수를 가진다고 표현하지 않는다.
- Figma 공식 문서의 자동 너비·자동 높이·고정 크기를 서로 다른 명시적 상태로 취급한다. 자동 너비일 때는 사용자가 Enter를 누른 줄만 강제 개행하며, 페이지 레이아웃 한계에서는 자연 줄바꿈을 허용한다.
- WCAG 2.2의 드래그 대체 조작과 키보드 접근 요구에 따라 선택·이동·크기 조절·취소는 버튼/숫자 입력도 제공한다.
- 참고: https://support.microsoft.com/en-us/powerpoint/add-text-to-a-slide · https://support.microsoft.com/en-us/office/keyboard-shortcuts-for-working-with-shapes-text-boxes-and-wordart · https://help.figma.com/hc/en-us/articles/27378154668951-Adjust-text-dimensions-and-resizing · https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements

## PowerPoint식 모델과 실제 웹 제약

| 동작 | 관리자에서 제공할 모델 | 안전 제약 |
| --- | --- | --- |
| 한 번 클릭 | 문구 상자 선택, 테두리·손잡이·현재 위치 표시 | 링크·폼은 편집 모드에서만 가로채고 공개 화면에는 개입하지 않음 |
| 두 번 클릭 / F2 / Enter | 선택 상자 안의 글자를 편집하고 커서를 복원 | 한글 IME 조합 중 DOM 교체 금지 |
| 테두리 드래그 | 선택 상자 이동 | 섹션 경계·기기별 초안·충돌 경고 |
| 오른쪽 손잡이 | 너비 조절, 자동/수동 모드 구분 | 최소 터치 영역 44px; % 너비로 저장 |
| 방향키·수치 입력 | 드래그와 동일한 결과 | 1px/Shift+10px, 잘못된 값은 적용 금지 |
| 상자 삽입 | 고유 ID·평문 원본·안정적인 섹션 앵커 생성 | 기존 문구와 이미지 위에 무단 덮어쓰기 금지, 임시저장 후 별도 게시 |
| 선택 글자 서식 | 플로팅 글꼴 창에서 범위별 글꼴·크기·색·강조 | 글자 선택 범위를 편집창 포커스 이동 뒤에도 보존 |
| 실행 취소/다시 실행 | 한글 조합 1회·문구 변경 1회·배치 변경 1회 단위 | 서버 새 버전 도착 시 오래된 되돌리기 금지 |

웹 페이지는 PowerPoint의 고정 슬라이드와 달리 반응형 문서 흐름이다. 따라서 자유 배치가 다른 문구를 가리거나 화면 밖으로 나가면 경고하고, 기존 공개 화면의 줄바꿈·간격·DOM은 편집 중에도 보존한다. `Ctrl+S`는 임시저장만 수행하고 게시는 별도 확인 동작으로 유지한다.

## 회귀 발생과 수정 기준

2026-09-24 실제 CMS 미리보기에서 제목 전체를 선택하기 위해 h2와 원래 줄 span 사이에 요소를 추가했다. 기존 `h2 > span` 스타일이 더는 적용되지 않아 두 줄이 한 줄로 붙었고, 편집 중에는 그 요소의 측정 폭이 매우 작아 세로로 줄바꿈됐다. 공개 제목의 DOM 계층을 복원하고, 선택 박스는 원문 DOM 밖에 별도 overlay로 그린다. 이 계층을 다시 변경하는 구현은 금지한다. 기존 각 줄을 유지하는 상태에서 전체 제목 선택은 별도 접근 가능한 목록/선택 모델로 설계한다.

## 단계별 완료 조건

1. **회귀 차단**: 공개 `/`의 소개와 입단 제목이 원래 span 직계 자식과 강제 줄바꿈을 유지한다. 등록된 초안/게시 변경은 삭제하지 않는다.
2. **기본 편집**: 선택·두 번 클릭·F2·편집 마침·취소가 서로 상태를 혼동하지 않는다. 편집창이 44px 세로 기둥이 되지 않고 원본 줄 너비와 정렬을 따른다.
3. **상자 배치**: 실제 텍스트와 선택 테두리의 좌표를 일치시킨다. 드래그, 44px 손잡이, 수치 입력이 같은 값을 만든다. 폭 변경은 기기별 초안에만 저장한다.
4. **상자 추가**: 앵커 탐색 실패 시 잘못된 임의 섹션에 추가하지 않는다. 안전한 본문 앵커를 명시하고, 생성 후 곧바로 새 상자를 선택할 수 있어야 한다. 삭제는 실행 취소 가능하고 게시 전 공개 페이지에 노출되지 않는다.
5. **서식**: 선택 범위별 글꼴·크기·색·B/I/U를 플로팅 창에서 수정한다. 원본과 다른 글자수에서도 스타일 범위를 정확하게 이동한다.
6. **출시 게이트**: 린트·타입·전체 단위 테스트·빌드·실제 관리자 브라우저와 공개 브라우저를 확인한다. 공개 디자인 동등성이 깨지면 배치 확장을 보류한다.

### 후속 실제 사용 검증

- 90% 확대 비율이 적용된 홈 소개 제목에서 마우스로 60px 이동한 결과를 실제 화면 좌표와 비교하고, 저장 좌표의 축척 오차를 수정했다. 되돌리기로 원위치를 복원했다.
- 홈 소개 제목을 고친 직후 이동 손잡이와 너비 손잡이를 각각 한 번의 포인터 제스처로 사용했다. 입력값과 배치가 모두 초안에 반영됐고, 두 변경을 각각 실행 취소해 기존 저장 초안 1건을 그대로 남겼다.
- 입단 안내의 다른 제목에서도 입력 직후 드래그 이동과 두 단계 실행 취소를 확인했다. 이 화면의 초안과 게시본은 검증 후 같았다.
- 긴 홈 소개 제목과 좁아진 상자에서 아래 문단·사진이 겹치지 않고 밀리는지 확인했다. 기본 문구의 공개 홈 DOM과 데스크톱·태블릿·모바일 가로 넘침은 변경되지 않았다.
- 대기 중 드래그의 즉각적인 테두리 피드백, 권한 거절 후 원위치 복구, 완료 상태 안내는 실패 테스트를 먼저 만든 뒤 고쳤다. 이는 추가 검증 사례이며 `20회 재귀 반복`을 수행했다는 주장은 아니다.
- 긴 제목의 전체 중앙이 화면 아래에 있더라도 보이는 부분의 중앙에 44px 너비 손잡이를 배치했다. 실제 관리자 미리보기에서 높이 약 1235px 제목의 손잡이가 900px 프레임 안에 남는 것을 확인했다.
- 선택 문구가 화면 밖으로 완전히 나가면 손잡이와 테두리가 숨고, 스크롤로 되돌아오면 다시 나타나는 것을 실제 화면과 회귀 테스트로 확인했다. 모바일 390px 미리보기에서도 가로 넘침은 없었다.

## 주의할 실패 경로

- 한국어 IME 입력 중 DOM 재생성/selection 손실.
- 드래그 중 부모 초안 sequence 변경, grant 지연, Esc 또는 pointercancel.
- 기존 고정 폭이 없는 공개 화면에서 의도치 않은 CSS 추가나 모바일 가로 overflow.
- 여러 CMS 원본을 한 카탈로그로 복제해 데이터가 어긋나는 문제.
- 새 문구 상자가 기존 페이지 링크·폼 위에 올라와 클릭을 가리거나, 소형 화면에서 가로 스크롤을 만드는 문제.
