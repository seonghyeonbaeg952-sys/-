# 공연 템플릿 캐러셀 — 기준 건축 개구부 레이어 규격

## 0. 범위와 결론

- 대상은 공연 섹션의 **3개 CMS 템플릿 캐러셀**이며 책 오브젝트가 아니다.
- 이 문서는 Figma/V4를 수정하지 않고, 기준 PNG와 현재 Figma 캡처의 구조를 측정한 레이어 재구축 규격만 정의한다.
- 기준 사진에 없는 독립 기둥, 별도 대들보, 바닥 그리드, 추가 원근선을 새로 만들지 않는다.
- 종이 입자, 미세 명암, 모서리 번짐까지 100% 일치시키려면 순수 벡터 재도안이 아니라 **동일 기준 PNG를 잠근 픽셀 베이스**로 사용해야 한다. 벡터는 템플릿 내용과 인터랙션에만 사용한다.
- 두 기준 PNG의 구조를 섞지 않는다. 현재 요구의 깊고 명확한 단차에는 `exec-90...`을 구조 마스터로 사용하고, `exec-70...`은 색감/질감 교차 확인용으로만 둔다.

## 3. 847 × 847 Figma 슬롯 환산

현재 Figma 무대 프레임 847 × 847에 맞추는 배율은 `847 / 1254 = 0.6754385965`이다.

### 핵심 환산 좌표

| 원본 | 847 슬롯 | 사용처 |
|---:|---:|---|
| x 180 | x 122 | 개구부 왼쪽 |
| x 1074 | x 725 | 개구부 오른쪽 |
| y 154 | y 104 | 개구부 위 |
| y 1040 | y 702 | 개구부 아래 |
| y 1058 | y 715 | 하단 베벨 종료 |
| y 1153 | y 779 | 안쪽 턱 종료 |
| y 1204 | y 813 | 앞쪽 받침 종료 |

따라서 **템플릿 가시 뷰포트**는 다음으로 고정한다.

```text
x = 122
y = 104
w = 603
h = 598
right = 725
bottom = 702
```

Figma에서 원본 1254 px 이미지를 매번 임의 스케일하지 말고, 한 번만 고품질로 847 × 847 파생 렌더한 파일을 기준 자산으로 만든다. 세 상태는 모두 같은 파생 자산을 참조해야 한다.

## 4. 정확한 픽셀 레이어 분해

한 장을 벡터로 따라 그리지 않는다. 같은 847 × 847 기준 비트맵을 중복 사용한다.

### A. 후면 베이스

```text
L00 · ARCHITECTURE · REAR BASE · LOCKED
x 0 / y 0 / w 847 / h 847
source: exec-90...의 847×847 파생 자산 전체
```

이 레이어가 후면 벽, 천장, 좌우 반환면, 하부 턱, 질감과 명암을 전부 가진다.

### B. 템플릿 덱

```text
L10 · CAVITY VIEWPORT · CLIP
x 122 / y 104 / w 603 / h 598
clip contents = on
```

세 개 템플릿은 완전한 앞면 그룹으로 이 뷰포트 안에 배치한다. 템플릿 이미지 자체를 잘라내거나 검은 띠를 따로 그리지 않는다.

### C. 전면 가림막

같은 기준 비트맵의 네 조각을 후면 베이스 위에 다시 올린다. 이미지 fill 좌표를 바꾸지 않고 원본 위치를 유지한 crop이어야 한다.

```text
L20A · FRONT FACADE · TOP       x 0   y 0   w 847 h 105
L20B · FRONT FACADE · LEFT      x 0   y 103 w 123 h 600
L20C · FRONT FACADE · RIGHT     x 724 y 103 w 123 h 600
L20D · FRONT FACADE · BOTTOM    x 0   y 701 w 847 h 146
```

- 조각 사이에 1 px 중첩을 둬 브라우저/Figma 소수점 샘플링의 흰 틈을 막는다.
- 네 조각은 새로운 흰 도형이 아니라 동일한 기준 PNG의 같은 픽셀이다.
- 이 방식으로 좌우 템플릿이 실제로는 완전한 앞면이지만 전면 구조 뒤에 들어가 일부만 보인다.
- 별도 기둥, 별도 lintel, 별도 sill을 이 레이어 위에 추가하지 않는다.

### D. 컨트롤

컨트롤과 상태 표시는 건축 레이어보다 위에 놓되 기준 구조를 덮지 않는 하단 안전 영역에 둔다.

```text
L30 · CONTROL · PREVIOUS
L31 · CONTROL · EXPAND ACTIVE TEMPLATE
L32 · CAROUSEL · COUNT
L33 · CONTROL · NEXT
```

## 5. 템플릿 3장 배치 수치

### 중앙 템플릿

현재 승인된 중앙 비율을 유지한다.

```text
x = 273.5
y = 211
w = 300
h = 413.5
scale = 1.00
```

- 개구부 좌우 여백: 약 151.5 px씩.
- 템플릿 하단은 y 624.5라 하부 베벨 y 702와 77.5 px 떨어진다.
- 템플릿의 검은 spine, 흰 앞면, 제목·날짜·장소·로고는 하나의 CMS 템플릿 컴포넌트다.

### 좌우 템플릿

중앙과 동일한 컴포넌트를 0.82배로 축소해 원근감을 준다.

```text
w = 246
h = 339.1
y = 248.2
```

가시 폭은 양쪽 모두 26 px로 맞춘다.

```text
LEFT full template:  x = -98   → right edge 148
LEFT visible area:   x 122–148 = 26 px (흰 앞면의 오른쪽 끝만 보임)

RIGHT full template: x = 699   → left edge 699
RIGHT visible area:  x 699–725 = 26 px (검은 spine만 보임)
```

이 배치의 효과:

- 왼쪽 템플릿의 검은 spine은 x -98 부근에 있어 완전히 가려지고 흰 앞면 끝만 26 px 보인다.
- 오른쪽 템플릿은 왼쪽 끝의 검은 spine 26 px만 보인다.
- 왼쪽 가시 끝 148에서 중앙 시작 273.5까지 125.5 px, 중앙 끝 573.5에서 오른쪽 시작 699까지 125.5 px로 내부 공기가 정확히 대칭이다.
- 좌우의 튀어나온 면적은 같고, 템플릿을 파괴적으로 crop하지 않는다.

## 6. CMS 캐러셀 상태 계약

템플릿은 모두 같은 `PERFORMANCE TEMPLATE` 컴포넌트이고 데이터만 달라진다.

| 상태 | 왼쪽 슬롯 | 중앙 슬롯 | 오른쪽 슬롯 | 표시 |
|---|---|---|---|---|
| State 01 | Event 03 | Event 01 | Event 02 | 1 / 3 |
| State 02 | Event 01 | Event 02 | Event 03 | 2 / 3 |
| State 03 | Event 02 | Event 03 | Event 01 | 3 / 3 |

- Next: `01 → 02 → 03 → 01`.
- Previous: `01 → 03 → 02 → 01`.
- 중앙 템플릿, 왼쪽 공연명·날짜·장소, 하단 활성 인디케이터, 상세 보기 링크, 템플릿 펼치기 대상이 한 상태에서 동시에 바뀐다.
- CMS 데이터가 1개면 중앙만 표시하고 좌우/화살표/카운트를 숨긴다.
- 2개면 두 상태만 순환하며 중복 복제해 3개처럼 보이게 하지 않는다.
- 3개 이상이면 최신/표시순 3개를 이 계약에 바인딩한다.

## 7. 템플릿 컴포넌트 계약

각 템플릿은 구조는 고정하고 다음 필드만 CMS에 바인딩한다.

```text
event_id
title
date
venue
series_label
display_order
is_visible
cover_variant (optional; 기본 템플릿 사용)
```

- 흰 앞면과 검은 spine의 너비 비율은 모든 슬롯에서 동일하다.
- 좌우 템플릿도 중앙과 같은 컴포넌트 인스턴스를 사용한다.
- 좌우 템플릿용으로 별도 검은 막대/흰 막대를 그리지 않는다.
- 템플릿 펼치기는 현재 중앙 `event_id`를 대상으로 한다.

## 8. 현재 Figma에서 제거해야 할 구조 오차

다음 요소는 기준 사진에 없거나 동일 구조를 중복 표현하므로 재구축 시 사용하지 않는다.

- `V8 · LAYER 01A · RECESSED CHAMBER PLANES`의 인공 투시 바닥선.
- 별도 후면 장식선과 수평 그리드.
- `V6 · DETACHED DEPTH PILASTERS` 같은 독립 기둥.
- 상부에 중복된 굵은 두 개의 보.
- 하부에 중복된 굵은 두 개의 보.
- 무대 양끝을 가득 채운 거대 흰 세로 블록.
- 좌우 템플릿을 대신해 별도로 그린 검은 막대.

기준 PNG에 이미 포함된 명암과 가장자리만 남겨야 한다.

## 9. 100% 일치 검증 절차

### 정적 픽셀 검증

1. 기준 1254 px PNG를 847 × 847로 한 번만 파생 렌더한다.
2. 빈 캐러셀 상태에서 Figma 무대만 847 × 847로 export한다.
3. 템플릿이 없는 부분의 기준 파생 이미지와 export를 Difference 모드로 비교한다.
4. 허용 기준: 구조 경계의 위치 오차 0 px, 평균 채널 오차는 동일 PNG 재사용으로 0에 가까워야 한다.
5. 1 px 밝은 틈이 있으면 전면 네 crop의 중첩을 1 px에서 2 px로 늘리고, 새로운 채움 도형으로 덮지 않는다.

### 상태 검증

- 세 상태에서 개구부와 전면 가림막의 위치는 한 픽셀도 움직이지 않는다.
- 좌우 가시 폭은 각각 26 px이다.
- 좌우 내부 공기 간격은 각각 125.5 px이다.
- 중앙 템플릿 좌표는 세 상태 모두 동일하다.
- Next/Previous 후 텍스트, 템플릿, 카운트, 활성 인디케이터가 같은 event를 가리킨다.

### 100%의 정확한 의미

- **건축 배경:** 동일 PNG 재사용으로 픽셀 일치 가능.
- **템플릿과 텍스트:** 실제 편집 가능한 Figma 요소이므로 승인된 컴포넌트 기준의 위치·크기·스타일 일치.
- 생성 PNG의 미세 입자와 복합 조명을 벡터로 다시 그려 100% 동일하게 만드는 것은 불가능하므로, 해당 영역을 벡터화하지 않는 것이 유일하게 정확한 방법이다.

## 10. 권장 최종 레이어 순서

아래가 Figma 레이어 패널의 위→아래가 아니라 **렌더링 뒤→앞** 순서다.

1. `L00 · ARCHITECTURE · REAR BASE · LOCKED`
2. `L10 · CAVITY VIEWPORT · CLIP`
   - `SIDE · LEFT · 0.82`
   - `SIDE · RIGHT · 0.82`
   - `ACTIVE · CENTER · 1.00`
3. `L20 · FRONT FACADE · EXACT PIXEL SLICES`
   - `TOP`
   - `LEFT`
   - `RIGHT`
   - `BOTTOM`
4. `L30 · CAROUSEL CONTROLS`
5. `L40 · QA OVERLAY` — 기본 숨김

이 순서가 “건물 안에 들어갔고, 양쪽에는 공기가 있으며, 전면 개구부가 템플릿 일부를 자연스럽게 가리는” 사용자의 요구를 충족한다.
